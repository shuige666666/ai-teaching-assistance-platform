# 09. v0.4 课程质量、幻灯片与互动开发方案

> 文档版本：0.4
> 状态：M7.0、M7.1 与 M8 已完成；M9 多样化已接入；M10 互动降级再生成已提前实现，其余再生成与配对验收待实施
> 前置条件：M1～M6.5 的 v0.3 基线持续可运行、可回归、可从 MySQL 恢复
> 核心取向：以 OpenMAIC 为参考系统，优先裁剪复用其已经跑通的生成—装配—渲染纵向链路，不另造更重的幻灯片架构

## 1. 决策结论

M1～M6.5 已经解决“系统能否可靠运行”的问题。v0.4 只集中解决两个用户当前最关心的问题：

1. 把现有单列文字堆叠的 slide，升级为主次清楚、接近课堂 PPT 的固定比例单页；
2. 加入按教学目的设计的 diagram/simulation/game/code 多样化互动场景。

`CourseBrief` 和大纲质量仍作为 M7.1 的必要前置，因为受众、难度、学习目标和课程时长会直接影响一页应该讲什么；但它不是新的主产品方向。LangGraph、多智能体、多模态、RAG、媒体生成、编辑器和导出均不进入 M7～M10 的当前主线。

实施顺序为：

```text
M7：CourseBrief 与更明确的大纲
  → M8：OpenMAIC 式 PPTElement 直接生成、规范化、装配和只读渲染
  → M9：OpenMAIC 式多类型互动 HTML 生成、保存和 iframe 运行
  → M10：单场景再生成与同题质量比较
```

M8 不再设计额外的语义中间格式、确定性排版引擎或复杂几何评分系统。模型按照从 OpenMAIC 裁剪后的 Prompt，直接返回具有坐标和样式的有限 `PPTElement[]`；服务端只做 JSON 解析、Schema 校验、默认值补齐、元素过滤、文本净化和 id 分配，然后组装为 `Slide`。这与 OpenMAIC 当前生产链路的核心方式一致，也最符合“先复刻一个成熟基座”的项目定位。

这里的“画布”只是 `Slide` 中 `1000 × 562.5` 的逻辑坐标平面，用来定位 React/SVG 元素，并不表示浏览器的 HTML `<canvas>` 标签，也不是另一种课程格式。课堂看到的仍是一张普通 React 渲染的 PPT 式页面。

## 2. 当前差距与最短改进路径

| 当前限制 | 直接后果 | v0.4 的处理 |
| --- | --- | --- |
| 用户需求没有结构化来源 | 后续模型可能遗漏或重新猜测受众、难度和目标 | M7.1 保存可追溯 `CourseBrief` |
| 大纲只描述标题、目标和关键点 | 场景容易重复，案例、练习和评估意图不明确 | M7.1 增加场景角色与有限课程记忆 |
| slide 使用段落、列表、提示块的单列文档流 | 页面更像 Markdown 讲义，视觉关系弱 | M8 改为模型直接生成有限坐标元素 |
| 正文和标题都偏大、单页文字过多 | 主次不明，课堂投屏时不易快速浏览 | 复用 OpenMAIC “slide 不是讲稿”的 Prompt 与字体/留白规则 |
| 当前模型契约主要约束字段和长度 | 合法 JSON 仍可能产生长段落 | 屏幕只保留短标题、要点和关系，细节继续进入 narration |
| 只有 slide/quiz | 学习者只能看和答，缺少过程操作 | M9 增加多样化互动 |
| ready 场景不能单独修改 | 一页不满意时只能重做整课 | M10 增加单场景再生成 |

这次优化不是“只换 CSS”，也不是“先建设一个通用 PPT 引擎”。Prompt、模型返回结构、装配、渲染和持久化必须一起形成最短纵向闭环，否则只改其中一端仍会得到不稳定结果。

## 3. v0.4 范围

### 3.1 必须交付

- M7.1：`CourseBrief`、字段来源、警告、Course v2 截止线和 `outline.v2`；
- M8：从 OpenMAIC `slide-content` Prompt 裁剪出的本项目 Prompt；
- M8：模型直接返回背景和带坐标的有限元素，首版支持 `text/shape/line/code`；
- M8：与 OpenMAIC 同构的 `Slide`，固定 `viewportSize: 1000`、`viewportRatio: 0.5625`；
- M8：轻量规范化、服务端 id 分配、富文本白名单净化、只读 `SlideCanvas` 与四类元素 Renderer；
- M8：新 slide 持久化到现有 MySQL Course v3，刷新后恢复同一页面；v1/v2 行保留但隐藏并明确拒绝读取；
- M9：diagram/simulation/game/code 的完整 HTML 生成、后处理、持久化和 iframe 运行闭环；
- M9：必要的 iframe 隔离、允许外部依赖的 CSP、最小消息校验和失败 fallback；
- M10：ready 场景按简短意见单独再生成，失败时保留旧场景；
- M10：使用 M7.0 同题基线，对课程内容和幻灯片效果做成对人工比较。

### 3.2 当前明确不做

- 不同时保留新的类 Markdown slide、纵向讲义或同一课程的第二套新 Renderer；
- 不引入通用自动排版器、全局碰撞求解、逐元素几何评分、自动美学打分或模型评审循环；
- 不复制 OpenMAIC 的图片、视频、图表、复杂 LaTeX、动画、聚光、激光笔和媒体生成链路；
- 不让普通 slide 执行 HTML/JavaScript；只有 M9 的独立互动场景可以在隔离 iframe 中运行脚本；
- 不建设通用 widget SDK；四种类型共享最小运行协议，不锁死玩法；
- 不在 M8～M10 实现拖拽编辑或 PPTX/ZIP 导出；二者分别保留为可选 M11、M12；
- 不做移动端、平板和小于 1280px 窄屏的专项适配；现有表现只按 best-effort 保留；
- 不引入 LangGraph、多智能体、多模态、RAG、联网搜索或自动事实核验。

如果后续需求变化，应先完成 M8 或 M9 当前纵向闭环，再决定是否扩展；不能把未来编辑和导出反向变成当前数据链路的前置工程。

## 4. CourseBrief：有信息就采用，无信息才补默认值

`CourseBrief` 不是要求用户填写完整表单，而是系统从“原始课程描述 + 可选高级设置 + 服务端默认值”得到的有效教学上下文。首页仍只要求 topic；高级设置可折叠且可选。

```ts
export interface CourseBrief {
  audience: string;
  learnerLevel: 'beginner' | 'intermediate' | 'advanced';
  learningGoal: string;
  prerequisites: string[];
  durationMinutes: 10 | 15 | 20;
  teachingStyle: 'structured' | 'case_based' | 'practice_oriented';
  interactionMode: 'off' | 'auto' | 'required';
  additionalRequirements: string[];
}

export type CourseBriefField = keyof CourseBrief;
export type BriefValueSource = 'explicit_setting' | 'prompt' | 'default';

export interface CourseBriefResolution {
  status: 'provisional' | 'resolved';
  sources: Record<CourseBriefField, BriefValueSource>;
  warnings: BriefResolutionWarning[];
  resolvedAt?: string;
}
```

字段合并顺序固定为：

```text
显式高级设置 explicit_setting
  > 原始描述中明确写出的要求 prompt
  > 服务端确定性默认值 default
```

用户如果写“面向大一零基础学生，用 15 分钟讲清 TCP 拥塞控制，学完能解释慢启动与拥塞避免的切换条件”，系统应把受众、水平、时长和学习目标标记为 `prompt`；用户没有写的先修知识、教学风格等字段才使用默认值。若用户只写“TCP 拥塞控制”，则未设置字段全部来自 `default`，不能让模型按学科自行猜测用户身份。

如果高级设置与原文冲突，高级设置胜出，同时保存 `SETTING_PROMPT_CONFLICT` 警告。字段缺失表示允许从 Prompt 或默认值补齐；显式空数组表示用户明确选择“无先修知识”或“无附加要求”，两者不能混淆。

推荐默认值保持为：

| 字段 | 默认值 | 用意 |
| --- | --- | --- |
| audience | `无特定专业背景的学习者` | 不擅自假定年龄、职业或专业 |
| learnerLevel | `beginner` | 给未说明难度的微课一个稳定起点 |
| learningGoal | `理解「{topic}」的核心概念、基本机制与典型应用` | 保证大纲有最低可用目标 |
| prerequisites | `[]` | 不凭空增加先修要求 |
| durationMinutes | `15` | 保持微课规模 |
| teachingStyle | `case_based` | 先建立问题情境，再解释机制 |
| interactionMode | `off` | 大纲页由用户选 `off/required`；不从描述自动开启，auto 仅保留内部枚举 |
| additionalRequirements | `[]` | 不替用户创造偏好 |

创建草稿时不增加模型调用。服务端先保存 provisional Brief；一次 `outline.v2.1` 响应同时返回从原文检测到的字段、警告和 outlines，不重复要求模型回传服务端可确定计算的 resolved Brief。服务端按上述优先级独占合并并在同一 revision 保存 Brief 与大纲。用户在确认大纲前修改 Brief 时，旧大纲失效并重新生成；场景已经生成后不直接修改整课 Brief。

## 5. M8：直接裁剪 OpenMAIC 幻灯片纵向链路

### 5.1 为什么采用这条链路

OpenMAIC 在当前固定提交中并不是先让模型输出抽象布局，再由一个独立排版系统计算所有坐标。它的主链是：Prompt 明确画布规格和版式规则，LLM 直接返回带 `left/top/width/height` 的元素 JSON，程序再做规范化和装配。因此本项目没有必要为了“更工程化”再添加一套不同架构。

本项目 M8 的链路固定为：

```text
CourseBrief + SceneOutline + 有上限的课程上下文
  → 裁剪后的 OpenMAIC slide-content Prompt
  → AIAdapter（mock / DeepSeek）
  → GeneratedSlideData：background + 带坐标的 elements
  → JSON/Schema 校验
  → 元素规范化、过滤、净化和服务端 id 分配
  → Slide { viewportSize: 1000, viewportRatio: 0.5625, elements }
  → Scene.content = { type: 'slide', canvas: Slide }
  → CourseRepository / MySQL
  → 只读 SlideCanvas
```

这条链保留本项目已经实现的 `AIAdapter`、调用预算、单场失败、MySQL revision 和 CourseRepository，只替换 slide 的模型契约与 Renderer。它既不是把 OpenMAIC 整仓复制过来，也不是重新设计另一个 PPT 系统。

### 5.2 数据契约

模型输出结构沿用 OpenMAIC `GeneratedSlideData` 的思想：模型提供视觉元素和背景，不提供课程实体 id、场景状态或数据库字段。

```ts
export interface GeneratedSlideSceneDTO {
  type: 'slide';
  content: {
    elements: GeneratedPPTElement[];
    background?: SlideBackground;
  };
  narration: string;
  summary: string;
}

export type GeneratedPPTElement =
  | GeneratedTextElement
  | GeneratedShapeElement
  | GeneratedLineElement
  | GeneratedCodeElement;

export interface GeneratedElementBase {
  left: number;
  top: number;
  width: number;
  height: number;
  rotate?: number;
}

export interface Slide {
  id: string;
  viewportSize: 1000;
  viewportRatio: 0.5625;
  theme: SlideTheme;
  elements: SupportedPPTElement[];
  background?: SlideBackground;
}
```

上面只展示公共骨架；四个 `Generated*Element` 分支分别对应 text、shape、line、code 的模型输入字段，完整的实体/模型字段分离见 [04-domain-model.md](04-domain-model.md) 第 16.4 节。

固定提交中的 OpenMAIC 生成响应列出了 `text/image/video/shape/chart/latex/line`，而它的 DSL 还定义了 `code`。本项目首版主动裁掉媒体、图表和复杂公式，只保留 `text/shape/line`，再把当前已经安全显示的只读代码块适配为 `code`。因此可以复用上游结构和 Renderer 思路，但不能声称 Prompt 与类型文件无需修改即可原样使用。

模型可以决定元素坐标、尺寸、颜色和文字层级，因为这些正是 OpenMAIC Prompt 已经约束和调试的部分；模型不能决定 `id`、Course/Scene 标识、order、status、revision、Action 或持久化元数据。服务端为通过校验的元素生成稳定 id。

新 slide 只允许 `content.canvas`，旧的 `content.blocks` 已从当前 Schema 与 Renderer 删除。因为这是删除字段并改变 Scene 内容联合，Course 截止线升级到 `schemaVersion: 3`；v1/v2 行不迁移、不删除，只由 Repository 列表过滤并在按 ID 读取时返回 `LEGACY_COURSE_UNSUPPORTED`。

### 5.3 Prompt 如何从 OpenMAIC 裁剪

应先复制固定提交中的 `slide-content/system.md` 与 `user.md` 到本项目 Prompt 模块，并保留其已经验证过的核心规则：

- 画布坐标为 `1000 × 562.5`，一页是投屏用幻灯片，不是文章或讲稿；
- 标题短、视觉层级明确，正文使用简短要点，详细解释放进 narration；
- 元素需要遵守安全边距、对齐、留白、字号和颜色对比；
- 根据内容关系选择标题区、卡片、步骤、对比等视觉组织，但直接输出最终元素；
- 返回单个严格 JSON 对象，不附加 Markdown 说明；
- 输出前自行检查文字是否塞得下、元素是否明显压在一起、页面是否存在无意义空洞。

随后只做与本项目范围直接相关的删改：

- 删除 image、video、chart、复杂 LaTeX 以及相关素材占位和生成说明；
- 把 CourseBrief、SceneOutline、已覆盖关键点、待覆盖目标和前页短摘要填入 User Prompt；
- 增加本项目 `code` 元素的 JSON 示例和行数建议，代码仍作为数据而不是可执行 HTML；
- 让 `remark` 或本项目既有字段承载 narration，不把讲稿塞进页面元素；
- 保持 DeepSeek 可稳定遵循的字段数量，不把上游所有可选视觉特性一起搬入。

Prompt 的第一次目标是复刻 OpenMAIC 的页面表达，不是立即形成“万能主题模板”。真实课程暴露的共同问题再反馈到 Prompt；不预先为每个学科设计大量分支。

### 5.4 规范化边界

模型返回之后只执行一层轻量处理：

1. 按现有规则提取并解析一个 JSON 对象，再执行 GeneratedSlideData Zod Schema；
2. 仅接受 `text/shape/line/code`，其他元素从本次结果中丢弃并记录诊断；
3. 对每个元素补齐 rotate、字体、颜色、线型等默认值，拒绝非有限坐标、非正尺寸和关键字段缺失；
4. 忽略模型提供的 id，并由服务端统一生成 id；
5. 对 text 的富文本做小型白名单净化，只保留项目实际渲染需要的 `p/span/strong/em/br` 和有限内联样式，移除脚本、事件属性、链接和未知标签；
6. code 内容始终按文本保存和渲染，不能进入 `dangerouslySetInnerHTML`；
7. 个别元素损坏时丢弃该元素；若最终没有任何可显示元素，则按现有场景生成失败处理。

这一层对应 OpenMAIC `normalizeElement`、元素后处理和 `scene-builder` 的职责。它不是排版器，也不负责重新计算整页结构。明显不美观的问题优先通过 Prompt 和示例调整；首版不为了消除所有重叠而引入通用碰撞算法。

OpenMAIC 的文本元素允许 HTML，Renderer 中存在富文本注入路径。本项目不能原样继承这条信任假设，所以增加上述单一白名单净化边界即可；没有必要把它扩展成通用 HTML 安全平台。

### 5.5 只读渲染

`SlideCanvas` 使用一个固定逻辑尺寸的相对定位容器，再根据外层可用宽高等比缩放。`SlideElement` 按元素 `type` 分发到 text、shape、line、code Renderer；元素坐标仍以 1000 为基准。它通常由 DOM 和 SVG 组成，并不是把整页绘制进 HTML `<canvas>`。

M8 只处理最新版 Chrome/Edge、`1280×720` 及更大的桌面课堂视口。页面应一次完整显示一张 16:9 幻灯片，不在幻灯片内部滚动；浏览器外层仍保留导航、进度和播放控件。页面外部不再重复大标题，只保留场景编号元信息；标题必须存在于 PPT 画布内，确保未来导出仍可见。损坏的单个生成元素在规范化时丢弃，不能让整页白屏。

视觉目标是“适合讲课的总结性页面”，而不是逐像素复制 OpenMAIC：

- 一页围绕一个主结论，标题不写成长句；
- 关键正文采用清晰的无衬线字体，标题、辅助说明和正文至少形成三级层次；
- 过程、对比和并列关系通过卡片、连线、色块和空间位置表达；
- 屏幕只显示可以快速扫读的内容，完整讲解继续由 narration 和 speech 承担；
- 颜色和装饰服务于信息关系，不为了“像 PPT”堆叠渐变、阴影和图形。

## 6. M9：多样化互动脚本（2026-08-31 需求修订）

### 6.1 类型与教学设计

保留 4～8 场景、默认 5，以及大纲页 off/required 显式选择。required 在 4/5～6/7～8 场景下分别安排 1/1～2/1～3 个互动；至少 2 个 slide、1 个 quiz，首场 slide、互动不相邻。

分类只用于选择 Prompt，不用于锁死玩法。当前支持 diagram（关系探索）、simulation（过程模拟）、game（操作挑战）、code（编程实验，Python/JavaScript）。3D、procedural-skill、多智能体和通用插件 SDK 不在本次范围。大纲新增可选 widgetOutline：designIdea 用简短文本描述学生操作、结果变化、反馈与完成条件；code 可带 language。大纲页可修改互动类型、设计意图和编程语言。

不要求每课凑齐所有类型，不新增玩法配额或趣味性评分门。diagram 可以分支追踪、逐步揭示或关系探索；simulation 必须让参数/状态参与实际计算；game 要有操作、后果与重试，不是换皮单选题；code 要编辑并真正执行当前源码，通过实际测试反馈。

Course 仍为 v4：新增枚举和可选字段，复用 Scene JSON 和 v1 消息，不建兼容分支、不回写旧课程。已保存 HTML 保持原样；新策略只作用于新生成结果。v1～v3 仍隐藏并拒绝读取。迁移 003 将数据库数量约束扩为 3～8（保留历史三场景行），新课程的 4～8 由领域层负责。

### 6.2 生成和运行

`outline.v2.3 → scene-interactive.v2 按 widgetType 分流 → AIAdapter（原始 HTML，不启用 JSON mode）→ 元数据/文档/大小校验 → Scene/MySQL → iframe`。元数据分别记录 scene-diagram/simulation/game/code.v2.3。diagram/simulation 输出预算 16,000 tokens，game/code 20,000；HTML 注入后不超过 256 KiB。复用现有最多四次上游调用、一次 repair，不增加浏览器自动修复或评审循环。

裁剪 OpenMAIC 四类 Prompt 的教学机制与实现提示，但用同一个平台注入的 InteractiveRuntime 提供 ready/onReset/reset/complete/error。完成条件由当前任务决定，不统一为点完节点。narration/fallback 仍为纯文本，普通 slide 代码块仍只读。

code 使用 InteractiveRuntime.runCode({language, code, timeoutMs})，在新 Worker 中执行，返回 stdout；Python 通过固定版本 Pyodide CDN 在浏览器加载，JavaScript 不支持 DOM/Node.js。每次运行独立状态，初始化上限 60 秒、默认执行 5 秒（最多 15 秒），停止/超时销毁 Worker。不是服务端代码执行平台，不承诺对任意恶意代码进行内存/CPU 配额隔离；模型必须使用该入口，不能在 UI 线程直接执行学生代码。学习过程的断言、语法与运行超时错误显示在页内，不触发整页 fallback。

### 6.2.1 布局骨架与课堂视口

Prompt 通过 `lib/interactive/layout-templates.ts` 提供三种可改写起点：主区 + 侧栏、主画布 + 底部控制条、编辑器 + 输出区。骨架统一要求 `min-height:0`、局部区域 `overflow:auto`、窄屏堆叠，并分别附上 SVG viewBox 收口、Canvas `ResizeObserver` 和集中式 reset 示例；它们只帮助模型组织页面，不锁死玩法，也不在服务端新增布局门禁。

Canvas 骨架使用独立定位容器，子 Canvas 不参与决定容器尺寸，避免“监听父尺寸 → 改子尺寸 → 父尺寸再次变大”的循环。resize 只更新有变化的像素缓冲区，render 只绘图。另附 running/ended、数值输入与正常失败示例；重置恢复全部默认参数，保留参数重跑应是独立操作。这些是本项目对上游设计思路的实现与适配，不声称原样复制了 OpenMAIC 完整模板。

课堂内 `InteractiveRenderer` 将 iframe 放入最大可用的 16:9 阅读窗口，工具栏保留在窗口外；这样固定比例只影响课堂展示，避免长页面把场景底部裁掉。导出的独立 HTML 不经过这个 React 外壳，继续由自身 `html/body` 和局部滚动规则自适应，符合 OpenMAIC `CanvasArea` 的展示/导出分离思路。

### 6.3 资源开放与必要隔离

允许 HTTP(S) 外部脚本、样式、图片和连接，无 CDN 域名白名单；Prompt 优先 HTTPS 固定版本成熟依赖。为运行环境允许动态执行与 blob Worker。移除旧源码 API 正则黑名单，不把正则扫描当作 JavaScript 安全证明。

iframe 仍只有 allow-scripts，没有 allow-same-origin、表单、弹窗、下载或顶层导航；CSP 仍关闭子 frame、object、base 和表单提交。平台不提供调用课程 API 的消息能力。允许联网意味着互动页可能向外发送用户输入，不应输入密钥、真实账号或敏感数据；CDN 不可用时不保证离线运行。localStorage/sessionStorage 仅提供页面内存兼容，不读取宿主存储。

这不是对所有请求的防火墙：同源隔离阻止读取宿主数据，不保证阻止脚本向本机接口发送请求。当前平台仍无账户/CSRF体系，只用于本机受信任内容演示，不接收未知来源的任意HTML；公开部署前必须另行确认接口鉴权与请求来源防护，本轮不扩成安全平台。

宿主校验当前 iframe source 与 v1 消息。第三方无关消息忽略，已识别协议的非法结构降级；30 秒未 ready、ResizeObserver 循环或其他未处理脚本异常显示纯文本 fallback，并卸载 iframe。布局通知曾导致真实页面持续变高，因此本轮恢复降级，不增加复杂启发式判断。新桥接通过 ERROR 的可选行列字段传递诊断，PING 重放首个启动错误；历史 WARNING 同样降级。用户可以重新加载原 HTML、跳过，或显式再生成本场互动；不自动调用模型。页内/宿主重置复用同一处理器，切页后的迟到消息忽略。

## 10. 止损规则

- 如果 M8 的真实模型 JSON 经常无法解析，先进一步缩小元素字段和 Prompt 示例，不增加新的排版层；
- 如果个别页面重叠，先调整 Prompt、内容预算或对应元素默认值，只有同类错误稳定复现后才增加一条针对性检查；
- 如果富文本净化成本开始扩张，首版可把 text 收缩为纯文本和少量强调，而不是引入完整 HTML 编辑器；
- 如果 diagram 的隔离或 fallback 尚不稳定，关闭 interactive 生成入口，先保留 M8 的静态课程闭环；
- 如果直接复用的上游模块牵出大量编辑器、媒体或存储依赖，应继续复制最小纯类型/纯函数，而不是引入完整 package；
- 如果 M7～M9 任一阶段破坏 M1～M6.5 回归，先恢复基线再增加功能。

这套方案的衡量标准不是“架构组件数量”，而是能否以较少代码复刻 OpenMAIC 已验证的页面表达和互动能力，并在本项目现有 MySQL、AIAdapter、课程状态与播放器中稳定运行。
