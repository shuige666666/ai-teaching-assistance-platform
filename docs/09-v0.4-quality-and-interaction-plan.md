# 09. v0.4 课程质量与互动能力开发方案

> 文档版本：0.4
> 状态：已完成方案设计，尚未进入代码实现
> 前置条件：M1～M6 的 v0.3 基线保持可运行、可回归、可从 MySQL 恢复
> 对应里程碑：M7；毕业论文研究延展顺延到 M8

## 1. 决策结论

M1～M6 已经解决“系统能否可靠运行”的问题，但当前课程仍以通用文字讲解、静态代码块和单选题为主。v0.4 不立即引入 LangGraph、多智能体、多模态、RAG 或媒体生成，而是集中解决两个产品问题：

1. 同一主题生成的课程能否更贴合学习者、目标和教学过程；
2. 课程能否至少包含一种安全、稳定、可操作的互动场景。

M7 采用下面的纵向路线：

```text
固定质量基线
  → 持久化 CourseBrief 与领域契约 v2
  → 大纲/场景 Prompt v2 与丰富静态内容块
  → interactive/diagram 自包含互动脚本
  → 规则质量门、单场景再生成与成对质量验收
```

互动场景不是多智能体能力。它仍由现有 GenerationService 调用一个模型生成，保存到 MySQL，再由固定 React 宿主中的 sandbox iframe 执行。M7 不引入新的编排框架。

## 2. 当前差距与对应改动

| 当前限制 | 直接后果 | v0.4 对策 |
| --- | --- | --- |
| 创建课程只输入主题和场景数 | 模型自行猜测受众、难度和学习结果 | 增加带服务端默认值的 `CourseBrief` |
| 大纲只有类型、标题、目标和关键点 | 容易重复“概念—机制—应用”的泛化结构 | 增加场景角色、误区、练习/评估意图 |
| slide 只有段落、列表、提示和代码 | 可见内容像纵向讲义，比较和过程难以表达 | 增加 steps、comparison、table 固定渲染块 |
| 场景只看到前一页摘要 | 跨页容易重复或遗漏目标 | 构造有上限的课程记忆：已覆盖、待覆盖、前文摘要 |
| repair 只修复结构错误 | JSON 合法不等于教学质量好 | 增加确定性质量报告和人工成对评价 |
| 只有 slide/quiz | 学习者只能阅读和作答 | 增加一种 `interactive/diagram` 场景 |
| ready 场景不能按意见重写 | 内容一般时只能整课重来 | 支持带简短指令的单场景再生成 |

Prompt 变长不是独立目标。只有字段、渲染器、校验器和运行时先具备表达能力，Prompt 才能要求模型生成相应内容。

## 3. v0.4 范围

### 3.1 必须交付

- `CourseBrief`：学习者水平、学习目标、先修知识、预计时长、教学风格和互动偏好；
- `schemaVersion: 2`、v1 → v2 迁移函数和 MySQL `brief_json` 迁移；
- `outline.v2`、`scene-slide.v2`、`scene-quiz.v2` 和 `scene-interactive-diagram.v1`；
- `steps`、`comparison`、`table` 三种固定 React 内容块；
- `interactive` Scene 与仅支持 `diagram` 的 `InteractiveContent`；
- 自包含 HTML/CSS/JavaScript 的解析、大小限制、静态安全检查、一次修复和失败隔离；
- 无 `allow-same-origin` 的 iframe 宿主、CSP、运行错误上报、重置和完成事件；
- ready 场景带用户指令的事务化再生成；
- 固定评价集、人工量表、基线/候选对比报告和 M6 全量回归。

### 3.2 明确不做

- LangGraph、教师/学生多智能体、圆桌讨论和角色扮演；
- PDF/Word/PPTX/图片输入、OCR、视觉模型、图片或视频生成；
- Web 搜索、RAG、引用溯源和自动事实核验；
- code widget、任意代码执行、simulation、game、3D 和 PBL；
- 外部脚本、CDN、iframe 内网络请求和跨页面共享身份；
- 自由坐标 PPT 画布、专业编辑器和复杂 Action 编排；
- 把 LLM-as-judge 分数作为在线硬门或事实正确性证明。

如果 diagram 纵向闭环尚未稳定，不得同时增加第二种 widget。

## 4. 课程需求与默认值

首页仍只要求用户填写主题。其余选项放在“课程设置”中，并由服务端写入规范化后的有效值，保证刷新和再生成使用同一上下文。

```ts
export interface CourseBrief {
  learnerLevel: 'beginner' | 'intermediate' | 'advanced';
  learningGoal: string;
  prerequisites: string[];
  durationMinutes: 10 | 15 | 20;
  teachingStyle: 'structured' | 'case_based' | 'practice_oriented';
  interactionMode: 'off' | 'auto' | 'required';
}
```

推荐默认值如下：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| learnerLevel | `beginner` | 不假定专业背景 |
| learningGoal | 根据主题生成的规范化默认目标 | 用户可以覆盖 |
| prerequisites | `[]` | 不凭空要求先修课程 |
| durationMinutes | `15` | 保持微课范围 |
| teachingStyle | `case_based` | 先用问题或案例建立动机，再解释机制 |
| interactionMode | `auto` | 只有确有教学价值时生成，且每课最多一个 |

`requestedSceneCount` 在 v0.4 仍保持 3～5，默认 5，避免同时扩大生成成本和播放器状态空间。`interactionMode=required` 主要用于演示与 E2E；`auto` 模式不能为了展示功能而给纯文本概念强塞互动页。

## 5. 计划领域契约

### 5.1 大纲

```ts
export type SceneTypeV2 = 'slide' | 'quiz' | 'interactive';

export type SceneRole =
  | 'hook'
  | 'concept'
  | 'mechanism'
  | 'worked_example'
  | 'practice'
  | 'summary'
  | 'assessment';

export interface SceneOutlineV2 {
  id: string;
  type: SceneTypeV2;
  role: SceneRole;
  title: string;
  teachingObjective: string;
  keyPoints: string[];
  misconceptions?: string[];
  assessmentFocus?: string;
  widgetType?: 'diagram';
  order: number;
  estimatedMinutes?: number;
}
```

课程级规则包括：第一场不能是 quiz；至少一个且最多两个 quiz；互动模式不是 `off` 时最多一个 interactive；interactive 不能作为第一场，必须服务于已经引入的概念；`required` 模式必须恰好生成一个 `widgetType=diagram` 场景。

### 5.2 丰富静态内容块

v0.4 保留现有四种 Block，只增加三个受控类型：

- `steps`：2～6 个有序步骤，每步包含短标题和说明；
- `comparison`：两个对象的 2～5 项同维度比较；
- `table`：2～5 列、1～6 行的短文本表格。

这些类型仍由固定 React 组件渲染，不允许模型返回 CSS、React 或任意 HTML。公式、图片和自由坐标布局不进入本版本。

### 5.3 互动内容

```ts
export interface InteractiveContent {
  type: 'interactive';
  widgetType: 'diagram';
  runtimeContractVersion: 1;
  html: string;
  fallback: {
    title: string;
    description: string;
    steps: string[];
  };
}
```

`html` 必须是一个完整、自包含的 HTML 文档，最大 100 KiB，不允许外部 URL、子 iframe、对象嵌入、表单提交或下载。fallback 始终由固定 React 渲染器显示加载说明，并在 iframe 失败时提供静态替代，不让单个互动脚本造成课堂白屏。

互动场景的 Action 先复用现有 `speech + learner pause`。iframe 发出合法的 `INTERACTIVE_COMPLETED` 后，播放器把它解释为当前 learner pause 已完成；M7 不为此引入通用 widget Action 系统。

## 6. 互动运行时安全契约

生成 HTML 一律视为不可信代码。它不能通过 `dangerouslySetInnerHTML` 进入主应用 DOM，只能进入独立 iframe：

```html
<iframe sandbox="allow-scripts" srcdoc="..." />
```

必须满足以下边界：

1. sandbox 只包含 `allow-scripts`，不包含同源权限、表单提交、顶层导航、弹窗或下载权限；
2. 宿主注入 CSP：默认拒绝所有资源，只允许内联样式、内联脚本和必要的 `data:` 图片，明确设置 `connect-src 'none'`、`form-action 'none'`、`worker-src 'none'` 和 `object-src 'none'`；
3. CSP 不允许 `unsafe-eval`；HTML/JavaScript 解析同时拒绝 `eval`、`Function`、动态 import、Worker、WebAssembly、外部 script/link、iframe、object、embed、meta refresh、`window.open`、location 导航、持续 `setInterval/requestAnimationFrame` 和明显无界循环；diagram 第一版只允许事件驱动 DOM 与 CSS transition；
4. 父页面只接受 `event.source === iframe.contentWindow` 且通过 Zod 的消息，不依赖 sandbox 的 `null` origin 判断身份；
5. 子页面只允许发送 `INTERACTIVE_READY`、`INTERACTIVE_COMPLETED` 和 `INTERACTIVE_ERROR`；父页面只发送 `INTERACTIVE_RESET`；
6. 5 秒未 ready、脚本运行异常或消息不合法时显示 fallback，并允许用户跳过或重新生成；
7. 切换场景、重播和卸载时清理 message listener、计时器和旧 iframe，拒绝迟到事件。

静态扫描只能减少明显风险，真正的隔离边界是 sandbox、CSP、无外部网络和严格的消息协议。

## 7. M7 开发分解

### M7.0：冻结质量基线

**任务**：建立 `eval/datasets/course-quality.v1.json`，覆盖概念解释、机制流程、编程实践三个类别，每类至少两个公开、无隐私主题；用当前 `outline.v1 + scene-*.v1` 生成基线，保存评分、Provider、模型、Prompt 版本、耗时、调用次数和 token 汇总。

**人工量表**：事实正确性、目标匹配、结构连贯、解释与案例价值、可见内容可读性、测验对齐度均使用 1～5 分；出现会误导学习者的关键事实错误时额外标记 `criticalError=true`。

**退出门**：评价集、评分说明和基线报告都可复现；此阶段不修改生产 Prompt。开发期只使用 6 个主题做快速对比，论文阶段若选择质量研究再扩大样本和重复次数。

### M7.1：CourseBrief、Schema v2 与 Prompt v2 大纲

**任务**：实现 Course v1/v2 判别读取、`migrateCourseV1ToV2`、`brief_json` 迁移、创建 API 可选 brief、首页折叠设置区、`outline.v2` 和编辑表单。旧 v1 课程必须可打开、播放，并在明确保存时迁移，不能要求清库。

**最小测试**：默认值规范化、非法枚举拒绝、v1 fixture 迁移、v2 MySQL 新实例恢复、brief 不被大纲请求临时覆盖、outline role/互动数量规则。

**退出门**：同一主题能分别按初学者和进阶目标生成明显不同但结构合法的大纲；M6 E2E 继续通过。

### M7.2：丰富 slide/quiz 与课程连贯性

**任务**：实现三种 Block Schema/Renderer/fixture，升级 slide/quiz Prompt；场景上下文加入有长度上限的 `coveredKeyPoints`、`remainingObjectives` 和前文摘要；严格区分可见短内容与 narration。增加重复内容、页面密度、关键点覆盖和 quiz—objective 对齐报告。

**最小测试**：每个 Block 的边界和转义、未知字段拒绝、移动/桌面渲染、课程记忆裁剪、重复和密度规则、mock 完整课程。

**退出门**：固定评价集的候选课程能够生成和恢复；没有通过增加长段落伪造“内容更丰富”。

### M7.3：interactive/diagram 纵向闭环

**任务**：扩展 Scene 联合、生成路由、专用 Prompt、HTML 校验和修复、InteractiveRenderer、iframe bridge、fallback、播放等待和 MySQL 恢复。mock 必须返回一个最小但真实可操作的 diagram HTML，而不是静态占位图。

**最小测试**：Schema/装配器、危险 HTML 拒绝、sandbox/CSP 属性、消息来源校验、ready 超时、runtime error、reset、completed、切页迟到事件、失败隔离和 production Chromium E2E。

**退出门**：在 `interactionMode=required` 下完成“创建 → 大纲含一个互动页 → 生成并持久化 → 课堂点击节点/逐步查看 → 重置 → 完成 → 刷新后重新加载”的完整链路；主页面 DOM、Cookie、localStorage 和网络不能被 iframe 访问。

### M7.4：单场景再生成与质量验收

**任务**：允许用户对 ready 场景提交不超过 500 字的修改指令；服务端读取现有场景作为有上限的 baseline，在不改变 Course.status、SceneProgress 或持久化 activeOperation 的情况下生成候选，最后以 expectedRevision 替换同 outlineId 场景。旧结果在新结果事务提交前保持可用，失败不能把 ready 场景改丢。quiz 再生成必须先提示旧作答会失效；用户确认后，替换场景与删除旧 sceneId 的 QuizAttempt 在同一 MySQL 事务提交。

**最小测试**：无指令/超长指令拒绝、模型不能修改 outlineId/order、成功替换而非追加、失败保留旧结果、并发冲突、quiz 作答确认/原子清理、互动页重新生成和 E2E。

**退出门**：完成 M6 全量回归和 v0.4 新增 E2E；同一固定模型配置下，v0.4 相对 v0.3 的成对人工评价达到 M7.0 冻结的阈值。建议初始阈值为：目标匹配、教学组织、案例/练习价值三项平均提升至少 0.5/5，事实正确性不得下降，至少 70% 的课程对更偏好 v0.4；同时报告而不隐藏延迟、token 和修复次数变化。

## 8. 推荐提交顺序

每个提交都必须保持主分支可构建，建议按以下顺序实施：

1. `docs/eval: 冻结 v0.3 质量基线与评分协议`；
2. `feat(domain): 增加 Course v2、CourseBrief 与迁移`；
3. `feat(course): 保存课程设置并升级 outline.v2`；
4. `feat(render): 增加 steps、comparison、table`；
5. `feat(generation): 升级 slide/quiz Prompt 与课程记忆`；
6. `feat(interactive): 增加 diagram 生成、校验与持久化`；
7. `feat(classroom): 增加沙箱 iframe 与互动完成协议`；
8. `feat(generation): 支持 ready 场景按指令再生成`；
9. `test/docs: 完成 v0.4 回归、质量报告与交付文档`。

Schema/迁移提交必须先于依赖它的 API 和 UI；InteractiveContent、生成器、Renderer 和 E2E 必须在同一个短分支中形成完整纵向闭环，不能把“类型已加入但页面无法处理”的中间状态长期留在主分支。

## 9. 测试与评价分层

| 层次 | 回答的问题 | 是否阻塞合并 |
| --- | --- | --- |
| Schema/纯函数 | 数据形状、迁移和不变量是否正确 | 是 |
| 组件与安全测试 | 固定 Block 和 iframe 宿主是否安全渲染 | 是 |
| API/MySQL 集成 | v2 保存、恢复、替换和冲突是否正确 | 是 |
| mock E2E | 不访问付费模型时完整产品链是否可重复 | 是 |
| DeepSeek smoke | 真实 Prompt 能否生成可用课程和互动脚本 | M7 退出时是，日常 CI 否 |
| 人工质量评价 | 内容是否比 v0.3 更适合学习 | M7 退出时是，单次提交否 |
| LLM-as-judge | 辅助发现可能问题 | 否，不能替代人工与事实核验 |

结构通过率、运行成功率和教学质量必须分别报告。互动页面能够加载，不代表互动具有教学价值；人工认为内容不错，也不能替代 sandbox 和错误恢复测试。

## 10. 止损与回退规则

- M6 的 `pnpm verify:full` 连续失败时停止扩展，先恢复 v0.3 回归；
- v1 课程不能读取或迁移时停止 Prompt/UI 开发，先修复兼容性；
- iframe 能访问主页面身份、发起外部网络请求或逃逸 sandbox 时，立即关闭 interactive 生成入口；
- 真实互动脚本在一次修复后仍频繁白屏时，不增加第二种 widget，先收紧模板与运行契约；
- 如果质量分数没有改善，先检查 CourseBrief 是否实际进入 Prompt、领域结构是否能表达要求和评分是否一致，不通过继续堆 Prompt 长度掩盖问题；
- M7 未达到退出门前，不引入 LangGraph、多智能体、多模态或 RAG。
