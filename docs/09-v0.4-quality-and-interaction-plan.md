# 09. v0.4 课程质量、画布与互动开发方案

> 文档版本：0.4
> 状态：方案已按 M7～M10 重分阶段；M7.0 六题输入、DeepSeek v0.3 自动基线和逐场景 MHTML 已完成，人工评分延后到 M10 配对验收；M7.1、M8、M9、M10 尚未实现
> 前置条件：M1～M6 的 v0.3 基线保持可运行、可回归、可从 MySQL 恢复
> 对应里程碑：M7 课程质量基础、M8 只读自由画布、M9 diagram 互动、M10 课程修订与验收；M11 画布编辑器可选，毕业论文研究延展暂存为 MX

## 1. 决策结论

M1～M6 已经解决“系统能否可靠运行”的问题，但当前课程仍以通用文字讲解、静态代码块和单选题为主。v0.4 不立即引入 LangGraph、多智能体、多模态、RAG 或媒体生成，而是集中解决三个产品问题：

1. 同一主题生成的课程能否更贴合学习者、目标和教学过程；
2. 静态场景能否从文字堆叠升级为可保存、可恢复、以后可编辑的 PPT 式画布；
3. 课程能否至少包含一种安全、稳定、可操作的互动场景。

M7～M10 采用下面的纵向路线，每个阶段都必须保持系统可运行并单独通过退出门：

```text
固定质量基线
  → Prompt 归一化 CourseBrief 与领域契约 v2
  → M8 受控布局生成 canvas.v1 与只读 SlideCanvas
  → M9 interactive/diagram 自包含互动脚本
  → M10 单场景再生成与成对质量验收
```

M8 的“自由画布”指持久化结果由绝对坐标元素组成，并不表示第一版把坐标、CSS 或 HTML 全交给模型。LLM 先输出语义内容和布局意图，服务端布局编译器产生稳定坐标；以后 M11 可以在相同 `canvas.v1` 上增加直接编辑。互动场景也不是多智能体能力，它仍由现有 GenerationService 调用一个模型生成，保存到 MySQL，再由固定 React 宿主中的 sandbox iframe 执行。M7～M10 不引入新的编排框架。

## 2. 当前差距与对应改动

| 当前限制 | 直接后果 | v0.4 对策 |
| --- | --- | --- |
| 当前只持久化主题和场景数，即使 Prompt 已写受众/难度/目标也没有结构化来源 | 后续模型各自猜测或遗漏要求，用户无法确认系统采用了什么 | 将 Prompt、可选高级设置和默认值归一为可追溯 `CourseBrief` |
| 大纲只有类型、标题、目标和关键点 | 容易重复“概念—机制—应用”的泛化结构 | 增加场景角色、误区、练习/评估意图 |
| slide 只有段落、列表、提示和代码 | JSON 无法表达并列概念、过程、对比等视觉关系 | M8 增加语义 `SlidePlanDTO` 和可编译的六种布局意图 |
| 当前 Renderer 使用单列文档流，正文使用大号展示字体 | 长段落获得接近标题的视觉重量，首屏被正文占满 | M8 建立 `1000 × 562.5` 逻辑画布、有限元素 Renderer、字体层级和溢出检测 |
| Prompt 只说明字段和宽松长度上限 | 模型容易把讲稿写进屏幕内容，结构合法但不适合快速浏览 | 严格区分可见摘要与 narration，冻结每种布局的内容预算 |
| 场景只看到前一页摘要 | 跨页容易重复或遗漏目标 | 构造有上限的课程记忆：已覆盖、待覆盖、前文摘要 |
| repair 只修复结构错误 | JSON 合法不等于教学质量好 | 增加确定性质量报告和人工成对评价 |
| 只有 slide/quiz | 学习者只能阅读和作答 | 增加一种 `interactive/diagram` 场景 |
| ready 场景不能按意见重写 | 内容一般时只能整课重来 | 支持带简短指令的单场景再生成 |

Prompt 变长不是独立目标。只有字段、渲染器、校验器和运行时先具备表达能力，Prompt 才能要求模型生成相应内容。

## 3. v0.4 范围

### 3.1 必须交付

- `CourseBrief`：受众、学习者水平、学习目标、先修知识、预计时长、教学风格、互动偏好和附加要求，并保存每字段来源、解析状态和警告；
- `schemaVersion: 2`、v1 → v2 迁移函数和 MySQL `brief_json` 迁移；
- `outline.v2`、`scene-slide-plan.v2`、`scene-quiz.v2` 和 `scene-interactive-diagram.v1`；
- `canvas.v1` 持久化契约：固定 `1000 × 562.5` 逻辑画布、稳定元素 id 和 `text/shape/line/code` 有限元素联合；
- `key_points`、`card_grid`、`process`、`comparison`、`code_explainer`、`summary` 六种受控布局意图，以及将语义计划确定性编译为画布元素的服务端布局编译器；
- 通用只读 SlideCanvas、元素分发 Renderer、legacy SlideContent v1 读取路径；
- 可见内容预算、布局/几何规则、确定性密度报告、`1280×720` 桌面 DOM 溢出检查和截图证据；
- `interactive` Scene 与仅支持 `diagram` 的 `InteractiveContent`；
- 自包含 HTML/CSS/JavaScript 的解析、大小限制、静态安全检查、一次修复和失败隔离；
- 无 `allow-same-origin` 的 iframe 宿主、CSP、运行错误上报、重置和完成事件；
- ready 场景带用户指令的事务化再生成；
- 固定评价集、人工量表、基线/候选对比报告和 M6 全量回归。

### 3.2 明确不做

- LangGraph、教师/学生多智能体、圆桌讨论和角色扮演；
- PDF/Word/PPTX/图片输入、OCR、视觉模型、图片或视频生成；
- Web 搜索、RAG、引用溯源和自动事实核验；
- code widget、任意代码执行、simulation、game、3D 和 PBL；
- 外部脚本、CDN、iframe 内网络请求和跨页面共享身份；
- 让 LLM 直接生成任意坐标、CSS、React 或画布 HTML；
- M8～M10 内的直接拖拽编辑、专业编辑器和复杂 Action 编排；可视化编辑仅作为不阻塞 v0.4 的可选 M11；
- 移动端、平板和小于 1280px 的窄屏专项布局、截图与 E2E；现有小屏样式只保留 best-effort，不作为退出条件；
- 把 LLM-as-judge 分数作为在线硬门或事实正确性证明。

如果 diagram 纵向闭环尚未稳定，不得同时增加第二种 widget。

## 4. 课程需求与默认值

`CourseBrief` 不是要求用户重复填写的一张完整表单，而是系统从“原始课程描述 + 可选高级设置 + 服务端默认值”中解析出的**有效教学上下文**。首页仍只要求用户填写主题或自然语言描述；高级设置保持可选。用户已经在描述中写明“面向大一学生、零基础、学完能独立实现一个 React 组件”时，系统应识别并复用这些信息，而不是再次要求填写，也不能让模型在后续每个场景中重新猜测。

原始 `topic` 必须按用户提交内容原样保存，不能被模型概括出的主题、受众或目标覆盖。M7.1 暂不为了命名整洁额外拆分 `requestText/title`；如果后续确需将“生成要求”和“课程标题”分列，应作为独立的数据迁移处理。

```ts
export interface CourseBrief {
  audience: string;
  learnerLevel: 'beginner' | 'intermediate' | 'advanced';
  learningGoal: string;
  prerequisites: string[];
  durationMinutes: 10 | 15 | 20;
  teachingStyle: 'structured' | 'case_based' | 'practice_oriented';
  interactionMode: 'off' | 'auto' | 'required';
  additionalRequirements: string[];
}

export type CourseBriefField = keyof CourseBrief;
export type BriefValueSource = 'explicit_setting' | 'prompt' | 'default';

export interface BriefResolutionWarning {
  code: 'SETTING_PROMPT_CONFLICT' | 'PROMPT_AMBIGUOUS' | 'SCOPE_TOO_BROAD' | 'LEGACY_DEFAULT_APPLIED';
  field?: CourseBriefField;
  message: string;
}

export interface CourseBriefResolution {
  status: 'provisional' | 'resolved';
  sources: Record<CourseBriefField, BriefValueSource>;
  warnings: BriefResolutionWarning[];
  resolvedAt?: string;
}
```

`audience` 表达“大一学生、企业新员工、准备面试的 Java 开发者”等具体对象，`learnerLevel` 表达其知识水平，两者不能互相替代。`additionalRequirements` 只保存用户明确提出、但不属于固定字段的教学约束，例如“必须包含代码示例”“不要使用数学推导”“多用真实案例”；模型不能根据学科自行补写偏好。

### 4.1 字段来源与合并优先级

每个最终字段都必须记录来源，合并顺序固定为：

```text
显式高级设置 explicit_setting
  > 原始描述中的明确要求 prompt
  > 服务端确定性默认值 default
```

这里的“明确要求”指可以从原文直接定位的信号，不是按学科常识推断。例如“给零基础高中生讲解”可以解析出 audience 和 beginner；只写“量子力学”不能因为主题较难就擅自判定 advanced。高级设置字段只有在请求中真实出现时才算 `explicit_setting`；字段缺失表示交给 Prompt 解析或默认值，显式空数组则表示用户明确要求“无先修知识”，不能与缺失混为一谈。

当描述与高级设置冲突时，高级设置胜出，并保存 `SETTING_PROMPT_CONFLICT` 警告供生成页展示。例如原文写“面向零基础”，高级设置选择 advanced，最终值是 advanced，但页面应提示发现了冲突，不能静默覆盖。原文内部含糊或互相矛盾时保存 `PROMPT_AMBIGUOUS`；范围明显超过 10～20 分钟微课时保存 `SCOPE_TOO_BROAD`。警告用于解释和提醒，不应让一次可安全默认的生成直接失败。

### 4.2 有信息和无信息时的处理

`POST /api/courses` 接收原始 `topic`、场景数和可选 `briefOverrides`。创建阶段不额外调用模型：服务端先用高级设置覆盖默认值，写入 `status=provisional` 的 brief。随后原有的 `outline.v2` 调用在同一个结构化响应中同时返回：原文中检测到的 brief 字段、解析警告、按优先级得到的 `resolvedBrief` 和课程大纲。服务端根据“高级设置 > 检测字段 > 默认值”重新计算最终 brief；如果模型返回的 `resolvedBrief` 与服务端结果不一致，则按大纲契约失败处理并进入既有受限 repair，而不是接受两份不同上下文。

因此这项能力不会固定增加一次 LLM 调用。正常路径仍是一次 `outline.v2` 请求；只有响应本身违反 Schema 或合并规则时，才与其他大纲错误一样消耗既有修复预算。最终 CourseBrief、来源、警告和大纲必须在同一短事务中保存，使“系统理解的要求”和“据此生成的大纲”保持同一 revision。

如果 Prompt 已经包含受众、难度或学习结果，就把这些明确字段标记为 `prompt` 并参与大纲设计，只为未提到的字段补默认值。如果 Prompt 只有主题，则所有未设置字段保持 `default`，模型不得偷偷添加无法追溯的受众假设。用户输入属于待解析数据；即使描述中出现“忽略系统规则、输出任意 HTML”等文字，也不能改变 System Prompt、JSON Schema、安全门或字段优先级。

推荐默认值如下：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| audience | `无特定专业背景的学习者` | 不擅自假定年龄、职业或专业 |
| learnerLevel | `beginner` | 不假定专业背景 |
| learningGoal | `理解「{topic}」的核心概念、基本机制与典型应用` | 服务端确定性模板；超长 topic 按 Schema 上限安全截断 |
| prerequisites | `[]` | 不凭空要求先修课程 |
| durationMinutes | `15` | 保持微课范围 |
| teachingStyle | `case_based` | 先用问题或案例建立动机，再解释机制 |
| interactionMode | `auto` | 只有确有教学价值时生成，且每课最多一个 |
| additionalRequirements | `[]` | 不替用户创造额外要求 |

`requestedSceneCount` 在 v0.4 仍保持 3～5，默认 5，避免同时扩大生成成本和播放器状态空间。`interactionMode=required` 主要用于演示与 E2E；`auto` 模式不能为了展示功能而给纯文本概念强塞互动页。

### 4.3 页面确认与重新生成边界

首页第一版只需把 audience、learnerLevel 和 learningGoal 作为可选高级设置，其余字段继续使用默认值；`interactionMode` 可在 M9 互动闭环接入时再显示。大纲页在模型返回后增加“系统理解的课程要求”摘要，为每个字段标记“高级设置 / 来自描述 / 默认值”，并展示冲突或范围警告。

用户在确认大纲前修改已解析 Brief 时，新值按 `explicit_setting` 保存，同时使当前大纲失效并要求重新生成；不能让旧大纲继续搭配新 Brief。M7.1 不允许在场景已经生成后直接修改整课 Brief，整课重规划属于后续受控再生成范围。这样既保留纠正模型理解的入口，也避免 CourseBrief、大纲和已生成场景出现版本错位。

## 5. 计划领域契约

### 5.1 大纲

```ts
export type SceneTypeV2 = 'slide' | 'quiz' | 'interactive';

export type SceneRole =
  | 'hook'
  | 'concept'
  | 'mechanism'
  | 'worked_example'
  | 'practice'
  | 'summary'
  | 'assessment';

export interface SceneOutlineV2 {
  id: string;
  type: SceneTypeV2;
  role: SceneRole;
  title: string;
  teachingObjective: string;
  keyPoints: string[];
  misconceptions?: string[];
  assessmentFocus?: string;
  widgetType?: 'diagram';
  order: number;
  estimatedMinutes?: number;
}
```

课程级规则包括：第一场不能是 quiz；至少一个且最多两个 quiz；互动模式不是 `off` 时最多一个 interactive；interactive 不能作为第一场，必须服务于已经引入的概念；`required` 模式必须恰好生成一个 `widgetType=diagram` 场景。

### 5.2 SlidePlanDTO 与 `canvas.v1`

当前 `SlideContent` 只说明“页面里有哪些 Block”，没有说明这些内容之间的空间关系。M8 将模型输出和持久化画布拆成两层：模型返回可校验的语义计划，服务端布局编译器把计划变成带绝对坐标的有限元素。这样既得到接近 PPT 的通用画布，也不要求 DeepSeek 稳定计算每个像素位置。

```ts
export type SlideLayoutPreset =
  | 'key_points'
  | 'card_grid'
  | 'process'
  | 'comparison'
  | 'code_explainer'
  | 'summary';

export interface SlidePlanDTO {
  layoutPreset: SlideLayoutPreset;
  subtitle?: string;
  content: KeyPointsPlan | CardGridPlan | ProcessPlan | ComparisonPlan | CodeExplainerPlan | SummaryPlan;
  narration: string;
  summary: string;
}

export interface CanvasSlideContentV1 {
  type: 'slide';
  schemaVersion: 2;
  format: 'canvas.v1';
  viewport: { width: 1000; height: 562.5 };
  layoutPreset: SlideLayoutPreset;
  background: CanvasBackground;
  elements: CanvasElement[];
}
```

六种布局负责表达主要信息关系，而不是把 Renderer 写成六套互不兼容的页面：

| 布局意图 | 主要用途 | 语义计划中的核心内容 | 典型 SceneRole |
| --- | --- | --- | --- |
| `key_points` | 一条核心定义加少量关键点 | definition + points + takeaway | hook、concept |
| `card_grid` | 2～4 个同层级概念并列 | cards | concept、summary |
| `process` | 步骤、循环或因果链 | ordered steps + loop flag | mechanism、worked_example |
| `comparison` | 两个对象按相同维度比较 | paired rows | concept、worked_example |
| `code_explainer` | 代码与解释并排 | code + annotations | worked_example、practice |
| `summary` | 收束本场景或整门课 | conclusions + takeaway | summary |

`scene-slide-plan.v2` 必须返回一个合法布局意图。布局不能由模型自由命名，也不能用 `key_points` 包装任意长文章。语义门先检查计划本身，例如 process 必须有 2～6 个步骤、comparison 必须逐行成对、code_explainer 必须包含代码；通过后才进入布局编译器。模型不得返回 id、坐标、zIndex、CSS、React 或 HTML。

v1 课程不能因为缺少 `format` 而无法恢复。Scene 联合继续接受旧版 SlideContent 并走 `legacy_stack` Renderer；旧 ready 场景只有在用户于 M10 明确再生成时才替换为 `canvas.v1`，不在读取或 Course v1 → v2 迁移中静默改写。

### 5.3 有限画布元素与布局编译

M8 第一版只实现四种元素：

- `text`：标题、subtitle、正文、要点和 caption；内容使用纯文本或受限的结构化 spans，不接受模型 HTML；
- `shape`：卡片、流程节点、强调背景和简单图形；颜色、边框、圆角只允许主题 token；
- `line`：分隔线、连接线和流程箭头，端点必须位于画布内；
- `code`：带语言和 caption 的只读源码，始终转义，不执行 HTML/JSX/TSX。

```ts
export interface CanvasElementBase {
  id: string;
  type: 'text' | 'shape' | 'line' | 'code';
  left: number;
  top: number;
  width: number;
  height: number;
  rotate: number;
  zIndex: number;
  semanticRole?: 'title' | 'subtitle' | 'body' | 'accent' | 'connector' | 'code';
}

export type CanvasElement = CanvasTextElement | CanvasShapeElement | CanvasLineElement | CanvasCodeElement;
```

布局编译器接收 `Scene.title + SlidePlanDTO + ThemeTokens`，由服务端生成所有 id、坐标、尺寸和样式 token，再执行 normalize 与几何语义门。必须检查数值有限、id 唯一、尺寸为正、边界安全、最小字号、zIndex 范围、文本容量、连接线端点以及明显的非预期重叠。允许卡片背景包含文字、连接线覆盖节点边缘等已声明关系；硬门不能把所有矩形相交一概判错。

OpenMAIC 可作为数据和渲染拆层的参照，但本项目采用更受控的生产输入：

| 参考点 | OpenMAIC 固定提交路径 | 本项目采用边界 |
| --- | --- | --- |

### 5.4 可见内容与 narration 契约

v2 将“屏幕上展示什么”和“讲解时说什么”视为两个不同产物：可见内容用于在数秒内识别结构和结论，narration 用于解释原因、例子、过渡和细节。减少屏幕文字不等于减少知识量，而是把详细教学内容移动到更合适的讲解层。

Prompt、Schema 和质量报告共同执行以下规则：

1. 每个 slide 只承担一个主要教学结论，标题不能同时包含多个并列教学任务；
2. 可见字段使用关键词、短语、短定义和要点，不使用“下面我们来看”等口语化过渡句；
3. narration 可以引用可见结构，但不能逐字复述整页，也不能把只有 narration 才出现的关键结论藏起来；
4. 标题、subtitle、Block 标题和要点不能大面积重复，页面末尾的 takeaway 必须提供新的收束而不是复制标题；
5. 模型不能为了满足 Block 数量虚构概念，也不能把一段长文机械拆成多张卡片。

以下数值作为 M8 Prompt v2、Schema 和质量门的初始工程目标；它们属于候选实现本身，不再伪装成 M7.0 对旧页面的密度评分。M8 实现后如需调整，必须依据固定 fixture 与 DOM 回归说明原因，不能只为让某门候选课程过门而临时放宽：

| 可见元素 | 结构硬上限或兼容边界 | v2 质量目标 |
| --- | --- | --- |
| Scene 标题 | 继续兼容现有 80 字符存储边界 | 通常 8～22 个中文字符，最多两行 |
| subtitle | 继续兼容现有 120 字符存储边界 | 不超过 36 个中文字符，最多两行 |
| 定义/正文文本元素 | v2 同一语义段最多 120 字符 | 通常 40～80 个字符，只写短定义或结论 |
| bullet/card/step 单项 | v2 单项最多 60 字符 | 通常不超过 30 个中文字符 |
| takeaway/强调文本 | v2 最多 120 字符 | 通常不超过 60 个中文字符 |
| code | 继续保留源码安全上限 | 建议 8～18 行；超长示例只展示关键片段并在 narration 解释 |

`visibleCharCount` 在折叠空白后统计标题、subtitle、caption 和所有可见说明，不统计 code 原文；代码另记 `codeLineCount` 和最长行。初始布局预算建议为：`key_points ≤ 160`、`card_grid ≤ 220`、`process ≤ 180`、`comparison ≤ 220`、`code_explainer ≤ 120`、`summary ≤ 150`。这些预算是可复现的工程起点，不等于教学质量分数，也不能替代人工判断。

### 5.5 桌面 Renderer 与视觉层级

Renderer v2 继续使用当前产品的米色纸张、红/绿强调色和整体编辑感，但重新分配字体职责：衬线展示字体只用于短标题或关键结论，正文、卡片要点和说明统一使用更适合屏幕阅读的无衬线字体。不能通过把所有文字加粗或持续缩小字号来解决内容过载。

建议冻结以下设计区间，并在实现时根据实际字体渲染截图微调一次：

| 层级 | 桌面端建议 | 说明 |
| --- | --- | --- |
| slide 主标题 | 34～42px，1.15～1.25 行高 | 最多两行，与外层场景导航标题区分 |
| subtitle/教学目标 | 18～22px，1.4～1.55 行高 | 使用次要颜色但保持可读对比度 |
| 卡片或步骤标题 | 20～24px，1.3～1.45 行高 | 不与正文共用展示级字号 |
| 正文和要点 | 16～18px，1.5～1.7 行高 | 默认无衬线，避免超长行 |
| caption/辅助信息 | 13～15px | 不能承担关键教学信息 |

桌面端的 slide surface 以 `1000 × 562.5` 的 16:9 逻辑画布为设计基准，在 `1280×720` 及更大标准课堂视口中等比缩放并完整落入可视区域，不依赖画布内部滚动才能读完。元素使用服务端布局编译器生成的确定性坐标，不使用模型原始坐标；正文和关键要点保持不低于 16px 等效字号，DOM 顺序应与视觉阅读顺序一致，颜色只用于增强分组，不能成为区分概念的唯一手段。

M8～M10 不为移动端、平板或小于 1280px 的窄屏设计专门重排规则，也不要求为 card_grid、comparison 或 code_explainer 增加移动端布局。已有媒体查询、自然缩放和小屏回退无需删除，但其效果仅为 best-effort，不纳入截图、E2E、质量评分或退出门。后续若明确需要移动端，再以独立范围补充断点、交互尺寸和视觉基线，不能在 M8 中顺带扩张。

布局编译器使用已有 `Scene.title` 生成带 `semanticRole='title'` 的画布元素，装配时两者来自同一个模型 DTO，不允许分别生成。M8 仍把 `Scene.title` 作为导航事实来源；若 M11 允许直接改标题，必须使用一个领域操作同时更新导航标题和画布标题元素，不能产生两份漂移内容。外层 `scene-heading` 只承担课程导航和场景定位，应比当前更紧凑。旧版 `legacy_stack` 保持可读但不追求新画布效果。

### 5.6 Prompt v2、布局选择与受限修复

布局意图在现有 scene 生成调用中一次性选择，不增加独立的“视觉设计 Agent”或额外规划调用。`SceneRole`、teachingObjective、keyPoints、CourseBrief 和受限课程记忆共同决定候选布局；Prompt 给出推荐映射，但允许模型在合法集合内选择更符合内容关系的布局。

`scene-slide-plan.v2` 至少明确：

- slide 是视觉辅助，不是 lecture script；详细解释进入 narration；
- 先识别内容关系，再选择布局，不允许所有页面都退化为 card_grid；
- 并列概念用 card_grid，步骤或循环用 process，同维度差异用 comparison，代码实践用 code_explainer；
- 每个可见字段遵守短文本目标，禁止整段口语、重复标题和无意义装饰文案；
- narration 解释因果、误区和例子，并与当前 SceneRole、学习者水平和前后页上下文一致；
- 只返回 Schema 允许的 JSON，不返回坐标、CSS、React 或可执行 HTML。

输出先经过 JSON/Schema、布局语义门和硬密度规则；通过后才调用确定性布局编译器，再经过元素 Schema、几何和安全门。布局计划非法、核心语义缺失、可见文字超过硬上限或出现明显重复时，可以复用现有一次模型 repair；编译器自身的确定性错误应修复代码或规则，不能浪费模型调用。repair 与传输重试继续共享现有最多四次上游调用预算，不能因为视觉优化暗中增加第五次调用。修复后仍不合格则按当前场景失败流程保存错误，已经完成的其他场景继续保留。

### 5.7 确定性质量报告与视觉证据

`lib/quality` 为每个 slide 生成可审计的报告，至少记录：

```ts
export interface SlideQualityReport {
  format: 'legacy_stack' | 'canvas.v1';
  layoutPreset?: SlideLayoutPreset;
  visibleCharCount: number;
  longestItemChars: number;
  elementCount: number;
  codeLineCount?: number;
  outOfBoundsElementIds: string[];
  unexpectedOverlapPairs: Array<[string, string]>;
  duplicateSignals: string[];
  densityStatus: 'pass' | 'warning' | 'fail';
  violations: string[];
}
```

服务端可以确定性检查字符、元素数量、坐标边界、尺寸、重复和代码行数，但不能仅凭几何框推断真实字体换行，也不能把所有预期的包含/连接关系误判为重叠。浏览器测试必须额外检查 slide surface 和文本/代码元素的 `scrollWidth/clientWidth`、`scrollHeight/clientHeight`，并在 `1280×720` 桌面视口保存场景截图。桌面 DOM 溢出断言阻塞合并，截图作为人工对照证据；在字体和运行环境稳定前，不启用容易误报的跨平台像素级硬门。移动端与窄屏不采集候选截图，也不形成失败判定。

Schema、安全、布局语义、几何边界和最终 DOM 溢出属于硬门；“布局是否最合适”“页面是否有吸引力”和“教学解释是否优秀”属于人工评价，不能伪装成确定性校验。结构合法、页面不溢出，也不代表事实正确或教学质量达标。

### 5.8 互动内容

```ts
export interface InteractiveContent {
  type: 'interactive';
  widgetType: 'diagram';
  runtimeContractVersion: 1;
  html: string;
  fallback: {
    title: string;
    description: string;
    steps: string[];
  };
}
```

`html` 必须是一个完整、自包含的 HTML 文档，最大 100 KiB，不允许外部 URL、子 iframe、对象嵌入、表单提交或下载。fallback 始终由固定 React 渲染器显示加载说明，并在 iframe 失败时提供静态替代，不让单个互动脚本造成课堂白屏。

互动场景的 Action 先复用现有 `speech + learner pause`。iframe 发出合法的 `INTERACTIVE_COMPLETED` 后，播放器把它解释为当前 learner pause 已完成；M9 不为此引入通用 widget Action 系统。

## 6. 互动运行时安全契约

生成 HTML 一律视为不可信代码。它不能通过 `dangerouslySetInnerHTML` 进入主应用 DOM，只能进入独立 iframe：

```html
<iframe sandbox="allow-scripts" srcdoc="..." />
```

必须满足以下边界：

1. sandbox 只包含 `allow-scripts`，不包含同源权限、表单提交、顶层导航、弹窗或下载权限；
2. 宿主注入 CSP：默认拒绝所有资源，只允许内联样式、内联脚本和必要的 `data:` 图片，明确设置 `connect-src 'none'`、`form-action 'none'`、`worker-src 'none'` 和 `object-src 'none'`；
3. CSP 不允许 `unsafe-eval`；HTML/JavaScript 解析同时拒绝 `eval`、`Function`、动态 import、Worker、WebAssembly、外部 script/link、iframe、object、embed、meta refresh、`window.open`、location 导航、持续 `setInterval/requestAnimationFrame` 和明显无界循环；diagram 第一版只允许事件驱动 DOM 与 CSS transition；
4. 父页面只接受 `event.source === iframe.contentWindow` 且通过 Zod 的消息，不依赖 sandbox 的 `null` origin 判断身份；
5. 子页面只允许发送 `INTERACTIVE_READY`、`INTERACTIVE_COMPLETED` 和 `INTERACTIVE_ERROR`；父页面只发送 `INTERACTIVE_RESET`；
6. 5 秒未 ready、脚本运行异常或消息不合法时显示 fallback，并允许用户跳过或重新生成；
7. 切换场景、重播和卸载时清理 message listener、计时器和旧 iframe，拒绝迟到事件。

静态扫描只能减少明显风险，真正的隔离边界是 sandbox、CSP、无外部网络和严格的消息协议。

## 7. M7～M11 开发分解

**2026-08-28 证据修订**：提交 `85be4b9f` 中的双视口截图、DOM/密度观察和评分空表被逐场景 MHTML 取代。既有 6 门 MySQL 课程不重新生成，报告保留原课程、narration、quiz、生成元数据和错误；MHTML 只承担静态留档和后续人类对照。M8～M10 仍只交付桌面端。

### M7.1：CourseBrief、Schema v2 与 Prompt v2 大纲

**任务**：实现 Course v1/v2 判别读取、`migrateCourseV1ToV2`、`brief_json` 迁移、创建 API 的可选 `briefOverrides`、首页折叠设置区、Brief 来源展示、`outline.v2` 同调用解析与大纲生成，以及确认前编辑/失效规则。创建时保存原始 topic 和 provisional brief；`outline.v2` 返回检测字段、警告、resolvedBrief 与 outlines，服务端按固定优先级复算，并把 Brief/Resolution/大纲在同一事务中保存。旧 v1 课程必须可打开、播放，并在明确保存时迁移，不能要求清库或重新生成旧内容。SceneRole 在这一阶段成为 M8 布局选择的稳定输入，但 M7.1 不提前修改 slide 样式或生产 scene Prompt。

**退出门**：同一原始描述在纯默认值与显式受众/目标设置下能生成有可解释差异且结构合法的大纲；有效 Brief、每字段来源、警告和大纲可从 MySQL 一致恢复；用户能看到系统采用了哪些描述信息并在确认前纠正；旧 v1 课程和 M6 E2E 继续通过。

### M8：PPT 式只读受控自由画布

M8 是 LLM 内容与版式优化的主要实现阶段，不能被简化成一次 CSS 调整，也不能把完整 OpenMAIC Editor 一起搬入。按以下内部顺序实施：

1. **M8.1—画布契约与旧数据兼容**：增加 `SlidePlanDTO`、`CanvasSlideContentV1`、`CanvasElement` 联合、Zod、几何语义门和 fixture；保留 v1 `legacy_stack` 读取路径；
2. **M8.2—布局编译与只读 Renderer**：实现六种语义布局到 `text/shape/line/code` 的确定性编译、16:9 SlideCanvas、元素分发、视觉层级和 fallback；
3. **M8.3—场景 Prompt v2 与课程记忆**：升级 slide/quiz Prompt；上下文加入有长度上限的 `coveredKeyPoints`、`remainingObjectives` 和前文摘要，严格区分可见短内容与 narration；
4. **M8.4—质量门与证据**：增加布局语义、几何边界、非预期重叠、重复、页面密度、关键点覆盖和 quiz—objective 对齐报告；只在 `1280×720` 桌面视口执行 DOM 溢出断言并保存截图。

**最小测试**：

- 四类 CanvasElement 的最小/最大边界、非有限数字、负尺寸、重复 id、未知类型、越界、普通文本 HTML 拒绝和 code 转义；
- 六种布局计划的合法/非法语义、确定性编译快照、允许包含/连接关系与非预期重叠区分；
- v1 `legacy_stack` 恢复和 M10 再生成替换路径；
- 标题、subtitle、单项、整页密度、重复信号、代码行数和 repair 预算；
- `1280×720` 桌面视口下的 DOM 顺序、水平/垂直溢出、最小字号和截图；
- 课程记忆裁剪、covered/remaining 一致性、quiz 对目标的引用和 mock 完整课程；
- DeepSeek smoke 中的布局分布、首次通过/repair 次数、token、耗时和最终页面截图。

**退出门**：固定 6 主题的候选课程能够生成、保存、重启恢复和播放；最终 `canvas.v1` 通过 Schema、安全、布局、几何和硬密度规则，在 `1280×720` 及更大桌面视口没有未声明溢出；v1 课程仍能打开；M6 全量回归继续通过。候选课程不能通过增加长段落、把关键正文或要点缩小到 16px 以下，或让元素跑出画布来伪造“更丰富”。完成后才开始 M9。

### M9：interactive/diagram 纵向闭环

**前置条件**：M8 的 `canvas.v1`、质量门、`1280×720` 桌面渲染和旧课程兼容已经通过退出门。若桌面静态课程仍频繁溢出或只能靠人工挑选好样本，不进入互动开发。

**任务**：扩展 Scene 联合、生成路由、专用 Prompt、HTML 校验和修复、InteractiveRenderer、iframe bridge、fallback、播放等待和 MySQL 恢复。mock 必须返回一个最小但真实可操作的 diagram HTML，而不是静态占位图。OpenMAIC 参考路径及本项目更严格的 sandbox 差异见 6.1 节。

**最小测试**：Schema/装配器、危险 HTML 拒绝、sandbox/CSP 属性、消息来源校验、ready 超时、runtime error、reset、completed、切页迟到事件、失败隔离和 production Chromium E2E。

**退出门**：在 `interactionMode=required` 下完成“创建 → 大纲含一个互动页 → 生成并持久化 → 课堂点击节点/逐步查看 → 重置 → 完成 → 刷新后重新加载”的完整链路；主页面 DOM、Cookie、localStorage 和网络不能被 iframe 访问。

### M10：单场景再生成与质量验收

**任务**：允许用户对 ready 场景提交不超过 500 字的修改指令；服务端读取现有场景作为有上限的 baseline，在不改变 Course.status、SceneProgress 或持久化 activeOperation 的情况下生成候选，最后以 expectedRevision 替换同 outlineId 场景。旧结果在新结果事务提交前保持可用，失败不能把 ready 场景改丢。quiz 再生成必须先提示旧作答会失效；用户确认后，替换场景与删除旧 sceneId 的 QuizAttempt 在同一 MySQL 事务提交。slide 修改指令可以要求“更精炼、改为对比、突出步骤”等受控变化，但最终必须重新经过 M8 的 `SlidePlanDTO → canvas.v1` 编译和同一质量门，不能给再生成开后门。

**最小测试**：无指令/超长指令拒绝、模型不能修改 outlineId/order、成功替换而非追加、失败保留旧结果、并发冲突、slide 布局变更仍通过几何/密度/溢出门、quiz 作答确认/原子清理、互动页重新生成和 E2E。

**退出门**：完成 M6 全量回归和 v0.4 新增 E2E；在相同六题、学习目标、Provider、模型、请求设置和 `1280×720` 视口下，对 v0.3/v0.4 做成对评价，样本顺序在条件允许时打乱。既定阈值保持为：目标匹配、教学组织、案例/练习价值、可见内容可读性、视觉层级与版式适配五项平均提升至少 0.5/5，事实正确性不得下降，桌面标准视口不存在硬溢出，至少 70% 的课程对更偏好 v0.4；同时报告延迟、token、首次通过率、repair 次数和布局分布。移动端证据不进入当前成对评价。

### M11：可视化画布编辑器（可选）

M11 不阻塞 v0.4，也不在本方案中默认排期。若 M8 通过后确认继续实现，第一批只做选择、拖拽、缩放、删除、撤销重做和 MySQL revision 保存；第二批再做文字编辑、复制粘贴、对齐吸附和图层。编辑器必须复用只读 SlideCanvas，通过操作/事务更新 `canvas.v1`，不能建立第二套页面格式。

OpenMAIC 可参考 [`packages/@openmaic/editor/README.md`](https://github.com/THU-MAIC/OpenMAIC/blob/59adbef03b63488a7ff1ea983cf0fbba51609f9f/packages/%40openmaic/editor/README.md)、[`src/core/index.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/59adbef03b63488a7ff1ea983cf0fbba51609f9f/packages/%40openmaic/editor/src/core/index.ts)、[`src/react/EditableSlideCanvas.tsx`](https://github.com/THU-MAIC/OpenMAIC/blob/59adbef03b63488a7ff1ea983cf0fbba51609f9f/packages/%40openmaic/editor/src/react/EditableSlideCanvas.tsx) 和 [`src/ui/EditableSlideCanvasWithUI.tsx`](https://github.com/THU-MAIC/OpenMAIC/blob/59adbef03b63488a7ff1ea983cf0fbba51609f9f/packages/%40openmaic/editor/src/ui/EditableSlideCanvasWithUI.tsx)。其中 core/react/ui 的拆分值得复用；OpenMAIC 的宿主状态和本地持久化方式不替代本项目的 MySQL 事务与 revision。

## 8. 推荐提交顺序

（以下仅是建议，开发者还是希望可以尽量减少commit次数，开发时假如认为需要commit时应该先请示开发者）

每个提交都必须保持主分支可构建，建议按以下顺序实施：

1. `docs/eval: 版本化并冻结桌面端质量基线与评分协议`；
2. `feat(domain): 增加 Course v2、CourseBrief 与迁移`；
3. `feat(course): 保存课程设置并升级 outline.v2`；
4. `feat(canvas): 增加 SlidePlanDTO、canvas.v1、有限元素与 v1 兼容`；
5. `feat(canvas): 增加六种布局编译、只读 SlideCanvas 和元素 Renderer`；
6. `feat(generation): 升级 slide/quiz Prompt、课程记忆与画布质量报告`；
7. `test(visual): 增加桌面端溢出断言、截图与 DeepSeek slide smoke`；
8. `feat(interactive): 增加 diagram 生成、校验与持久化`；
9. `feat(classroom): 增加沙箱 iframe 与互动完成协议`；
10. `feat(generation): 支持 ready 场景按指令再生成`；
11. `test/docs: 完成 v0.4 回归、成对质量报告与交付文档`。

Schema/迁移提交必须先于依赖它的 API 和 UI。`canvas.v1` 的领域提交可以先进入主分支，但必须保持 v1 Renderer 和 fixture 全绿；布局编译器、只读 Renderer、Prompt 和质量门应连续完成，不能让生产 Prompt 输出暂时无法编译或渲染的计划。InteractiveContent、生成器、Renderer 和 E2E 必须在同一个短分支中形成完整纵向闭环，不能把“类型已加入但页面无法处理”的中间状态长期留在主分支。

## 9. 测试与评价分层

| 层次 | 回答的问题 | 是否阻塞合并 |
| --- | --- | --- |
| Schema/纯函数 | 数据形状、迁移和不变量是否正确 | 是 |
| 布局与几何规则 | 内容关系、编译结果、坐标边界、字符预算和重复是否符合确定性规则 | 是 |
| 组件与安全测试 | CanvasElement、SlideCanvas 和 iframe 宿主是否安全渲染 | 是 |
| 桌面端 DOM/截图 | `1280×720` 页面是否溢出、遮挡、顺序错乱或靠过小字号勉强容纳 | DOM 断言是；首版截图人工审查是 M8 退出门 |
| API/MySQL 集成 | v2 保存、恢复、替换和冲突是否正确 | 是 |
| mock E2E | 不访问付费模型时完整产品链是否可重复 | 是 |
| DeepSeek smoke | 真实 Prompt 能否生成可用画布课程和互动脚本 | 对应 M8/M9 退出时是，日常 CI 否 |
| 人工质量评价 | 内容是否比 v0.3 更适合学习 | M10 退出时是，单次提交否 |
| LLM-as-judge | 辅助发现可能问题 | 否，不能替代人工与事实核验 |

结构通过率、运行成功率和教学质量必须分别报告。互动页面能够加载，不代表互动具有教学价值；人工认为内容不错，也不能替代 sandbox 和错误恢复测试。

## 10. 止损与回退规则

- M6 的 `pnpm verify:full` 连续失败时停止扩展，先恢复 v0.3 回归；
- v1 课程不能读取或迁移时停止 Prompt/UI 开发，先修复兼容性；
- 新画布只有在缩小正文字号、隐藏内容或允许内部滚动时才不溢出，说明语义计划或布局编译器容量错误；回退 Prompt/编译规则，不接受视觉掩盖；
- Prompt 已要求 card/process/comparison，但 `SlidePlanDTO` 或布局编译器无法表达对应关系时，先补齐结构，不继续堆叠自然语言指令；
- 模型直接返回任意坐标、CSS 或 HTML 导致不稳定时，立即退回语义计划 + 服务端布局编译，不能依赖更多 repair 掩盖架构问题；
- M8 未通过 `1280×720` 桌面硬门和 v1 恢复回归时，不开始 interactive/diagram；
- iframe 能访问主页面身份、发起外部网络请求或逃逸 sandbox 时，立即关闭 interactive 生成入口；
- 真实互动脚本在一次修复后仍频繁白屏时，不增加第二种 widget，先收紧模板与运行契约；
- 如果质量分数没有改善，先检查 CourseBrief 是否实际进入 Prompt、领域结构是否能表达要求、布局选择和编译是否匹配内容关系、可见内容是否与 narration 分工以及评分是否一致，不通过继续堆 Prompt 长度掩盖问题；
- M10 未达到退出门前，不引入 LangGraph、多智能体、多模态或 RAG；M11 也不得被当作修复内容质量问题的捷径。
