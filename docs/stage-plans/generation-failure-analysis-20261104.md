## 已确认的代码问题与因果边界

### 互动 HTML 识别过于依赖开头格式

`lib/generation/scene-schema.ts:85` 仅在输出去除包围整个响应的代码围栏后，以 doctype/html 开头时走 HTML 分支，否则交给 `parseModelJson`。这意味着完整 HTML 前多出一句说明、注释或围栏外文字，仍可能被送入 JSON 提取；提取器会错误读取 scene-meta 或 CSS/JavaScript 花括号。

离线使用同一份合法完整 HTML 验证：原文通过；添加前导注释或说明后，出现 `type 必须为 interactive`、`content 缺失`、`fallback 为额外字段`；添加说明和 HTML 围栏后，出现“提取到的 JSON 对象仍无法解析”。两种错误与本次日志相符。

**边界：** 本次失败原始模型响应未落盘，只能确定实际进入了 JSON 解析/校验分支，并确认该识别缺陷可复现；不能断言原始响应一定完整，或一定带某一种前缀。不能根据这项离线实验宣称修复后本次两页互动必然成功。

### 场景修复未继承首轮的思考模式

`lib/ai/openai-compatible-adapter.ts:53` 只在 `stage === "scene"` 时发送 `thinking.type=disabled`。进入 `repair` 后省略这个参数。当前配置使用官方 DeepSeek 接口；其[思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)明确说明默认启用思考，默认强度 high。

因此首轮与修复阶段使用不同的思考策略。日志显示首轮互动约 25～28 秒返回文本；修复多次耗时约 80～90 秒，`finishReason=length`，五次正文为空，另外的截断正文也不完整。该配置差异与修复开销激增、输出截断高度吻合。原始响应未保留，不能量化其中具体多少 token 用于推理。

### 截断响应被按普通上游异常原参数重试

`lib/ai/openai-compatible-adapter.ts:109` 将空 content 映射为可自动重试的 `AI_UPSTREAM_ERROR`，没有根据 `finishReason=length` 区分预算耗尽。`lib/generation/scene-pipeline.ts:101` 因而在相同参数下重复发起修复。第 3 页连续三次得到空正文加 length，第 6 页两次得到相同结果后返回截断正文。这解释了等待很久仍失败；增加重试次数无法针对这类失败修正原因。

### 长 HTML 的修复上下文可能被截去脚本尾部

`lib/generation/prompts/scene-repair.v1.ts:8` 对所有类型统一使用 `rawOutput.slice(0, 10_000)`。互动修复依然要求重新生成完整 HTML，但长文档只保留头部。离线构造 12,331 字符的合法文档后，修复上下文确实丢掉末尾脚本和 `</html>`。这是已确认的上下文截断风险；本次未保存原文，不能断言每次互动修复都因此受损。

## 幻灯片失败与诊断限制

第 1、2 页首轮均报 JSON 解析失败。它们的 finishReason 为 stop，输出分别为 1,098 / 846 tokens，没有达到 slide 的 8,000 输出上限；第 2 页修复成功，第 1 页修复失败。因此不能把这两页归因为相同的长度上限问题，也没有证据将其归因为高亮引用校验。

第 1 页修复阶段还存在诊断信息保真问题：`scene-pipeline.ts:166` 仅保留 `InvalidSceneError`，若修复阶段再次抛出 `InvalidOutlineError`，会复用首轮 issues。后续应保留最终解析错误的固定诊断。

当前日志没有失败正文的受控留样，空正文响应的 usage 也未进入成功结果累计，本次运行 `usage_status=partial`。运行表中的 token 总数不能当成完整计费依据。

## 建议修复顺序

1. 修正互动响应识别：兼容前导说明、注释和代码围栏；明确区分完整 HTML 与旧 JSON DTO，继续执行原有文档与脚本校验。
2. 显式统一场景生成与场景修复的思考模式，不依赖服务商默认值；大纲推理策略单独保留。
3. 对 length 截断单独分类，取消无变化的空正文重试；采用受限的精简重生成或清晰终止，保持现有调用预算。
4. 按场景格式提供修复上下文。对长 HTML 保留有效脚本和文档结构，避免简单截去尾部；补充受控失败留样及最终错误原因。
5. 先用离线回归验证以上边界，再对这次失败页面做有界真实模型复验。生成成功后仍需检查真实玩法，不能只以保存成功作为质量结论。

上一轮分段讲解的真实模型验收只有一页 slide，未覆盖本次互动修复路径。此前单元、mock E2E 和 MySQL 测试通过证明工程路径可运行，不构成真实模型在不同内容类型上的成功率验证。

## 2026-11-04 修复和复测

场景生成与场景修复都显式关闭 DeepSeek 思考模式。HTTP 返回空正文且结束原因是 `length` 时按截断处理，停止原参数自动重试。截断但有正文时使用现有的一次修复预算请求精简的完整页面。互动修复上下文保留限额内的完整 HTML，超过限额时根据原任务精简重生成。

互动解析兼容文档外的说明、注释和代码围栏。提取后的文档继续经过元数据、HTML 大小和内联脚本语法校验。幻灯片回放发现两种反复出现的标点错误，分别是 `content` 缺少闭合括号与 `targetRefs` 缺少开引号。场景解析对这两种情况做本地恢复，之后仍按原场景契约校验。

复测使用同一份 8 页大纲和本机配置的 DeepSeek V4 Flash，课程单独写入 MySQL。首次复测 8/8 页完成，两页互动均一次生成成功，分别约 26.3 秒和 25.5 秒。场景阶段共 11 次远端调用，耗时约 92 秒，3 页幻灯片经过远端修复。这三份原始响应随后使用最终代码离线重放，均在单次输出内解析、校验和装配成功，讲稿与远端修复产物中的段落和引用一致。

另在一份真实互动产物中加入可复现的脚本语法错误，单独验证修复链路。一次 DeepSeek 修复用时约 21 秒并通过完整校验。真实复测、该修复探针与后续模拟页重生成合计 13 次远端调用，均未复现空正文或长度截断。这一轮只覆盖《中国地貌概况》这份固定大纲。
