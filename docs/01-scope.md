# 01. 项目范围与版本边界

> 文档版本：0.4
> 状态：v0.3/M1～M6.5、v0.4/M7.0、M7.1 与 M8 已完成；人工评分延后到 M10 配对验收；M9 已完成；M10 尚未实现，M11 编辑器和 M12 导出可选
> 适用阶段：毕业设计复刻项目的工程质量增强阶段

## 1. 核心结论

本项目的第一目标是独立实现一个可以运行、可以演示、可以测试的 AI 教学辅助系统，而不是逐项复制 OpenMAIC 的全部能力。第一版只保留参考系统中最稳定的主链：

```text
输入教学主题
  → 生成结构化课程大纲
  → 生成 4～8 个教学场景
  → 用固定 React 组件渲染
  → 按 Action 顺序播放讲解与测验
  → 保存到 MySQL 并再次打开课程
```

这条链路已经在 M1～M6 完成，M6.5 又补齐远端响应分类、受限重试和脱敏可观测性，共同形成冻结的 v0.3 工程基线。下一阶段先提升课程质量并加入一种受控互动场景，再进入毕业论文研究延展；不因为基线完成就同时引入所有 OpenMAIC 平台能力。

## 2. 参考系统分析与裁剪原则

OpenMAIC 当前是平台级项目，包含课程生成、四类场景、动作播放、多智能体讨论、白板、TTS/ASR、媒体生成、PBL、编辑器、导入导出、多 Provider、本地与服务端存储等能力。其可复用的核心思想不是完整功能清单，而是以下四点：

1. 用稳定的领域模型描述课程，而不是让模型生成 React 源码；
2. 把大纲生成和逐场景生成分开，使单个失败可以定位和重试；
3. 把讲解行为表示为 `Action[]`，由确定性播放器执行；
4. 在每个模型输出边界进行解析、校验、标准化和错误分类。

本项目采用“保留主干、缩小实现”的裁剪原则：

| OpenMAIC 设计 | 本项目 MVP 决策 |
|---|---|
| `Stage → Scene → Action` | 简化为 `Course → Scene → Action`，保留相同职责边界 |
| slide、quiz、interactive、PBL | 只实现 slide 和单选 quiz；slide 增加静态代码块 |
| 大纲、内容、动作分段生成 | 保留大纲与场景分段；MVP 场景接口一次返回内容和讲解文本 |
| 大量动作类型 | 只实现 speech 和 pause |
| 多 Provider 与按阶段路由 | MVP 只验收 mock 与 DeepSeek；百炼兼容档保留为后续可选扩展 |
| IndexedDB 与 HTTP/PostgreSQL 双后端 | 使用服务端 MySQL 作为唯一课程事实来源 |
| LangGraph 多智能体讨论 | 不进入 MVP，作为后续候选扩展 |
| PPTX、HTML、视频导出 | 不进入 MVP；只含 PPTX 与互动 HTML 的简化资源包暂存为可选 M12 |

参考源码定位（均指 OpenMAIC 参考仓库）：

- 领域契约：`packages/@openmaic/dsl/src/stage.ts`、`action.ts`；
- 浏览器生成主链：`app/page.tsx` → `app/generation-preview/page.tsx` → `app/classroom/[id]/page.tsx`；
- 分阶段生成：`app/api/generate/scene-outlines-stream`、`scene-content`、`scene-actions`；
- 动作与播放：`lib/action/engine.ts`、`lib/playback/engine.ts`；
- 默认本地存储：`@openmaic/storage` 的 `BrowserDocumentStore`；
- 多智能体边界：`lib/orchestration/director-graph.ts`。

## 3. 目标用户与核心场景

MVP 只有一个本地用户角色，可以同时扮演课程创建者和学习者，不设计账号、权限和多人协作。

核心场景为：

> 用户输入“TCP 拥塞控制”等教学主题，系统生成 4～8 个有顺序的教学场景。用户确认大纲后等待场景生成，随后进入课堂页面，阅读包含文本或静态代码块的幻灯片、完成单选测验，并在关闭页面后从 MySQL 历史课程中重新打开。浏览器语音只作为可选播放方式。

## 4. v0.3 MVP 范围（已完成）

### 4.1 必须实现

#### 课程创建

- 主题为必填文本，去除首尾空白后长度为 2～500 个字符；
- 场景数量固定在 4～8 个，默认 5 个；
- 创建时由服务端分配 `courseId`，并在返回前把草稿写入 MySQL；
- 模型配置仅来自服务端环境变量。

#### 大纲生成与确认

- 生成课程标题和有序 `SceneOutline[]`；
- 大纲只允许 `slide` 和 `quiz`；
- 用户可以修改场景标题、教学目标和关键点；
- 用户确认后才开始生成完整场景；
- 大纲失败时保留原主题并允许重试。

#### 场景生成

- 每个大纲独立生成，不能因为单页失败丢失其他成功页面；
- slide 使用固定内容块渲染器，支持段落、列表、提示块和只读代码块；
- 代码块支持语言标记、转义显示和语法高亮，不执行模型返回的代码；
- quiz 首版只支持单选题；
- 场景包含讲解文本，由程序转换成 `speech` Action；
- 每个场景有 `pending / generating / ready / failed` 状态；
- 失败场景可以单独重试。

#### 课堂播放

- 显示当前场景、总场景数和课程标题；
- 支持上一页、下一页、开始、暂停和继续；
- 讲解文本必须可见，播放器可以按估算时长推进；
- Web Speech API 是可选 SpeechAdapter，启用时负责朗读，不可用时自动使用纯文本适配器；
- quiz 提交后显示正确性和解析；
- 课程到达末页后进入完成状态；
- 浏览器不支持语音时仍能阅读讲解文本，不能阻塞课程。

#### 数据库持久化

- MySQL 是课程聚合根的唯一事实来源；
- 首页通过服务端 API 显示历史课程；
- 刷新生成页后能够读取已有进度；
- 刷新课堂页后能够重新加载课程；
- 支持删除单门课程；
- 每次大纲或场景状态变化都由服务端校验并事务保存；
- 数据库不存储 API Key、完整 Prompt 或原始模型响应。

#### 基础质量保障

- 所有外部输入和模型输出经过 Zod 校验；
- 认证错误与格式错误不能无限重试；
- 核心领域逻辑有 Vitest 测试；
- 至少有一条 Playwright happy path；
- `pnpm lint`、`pnpm test`、`pnpm build` 在交付时通过。

### 4.2 v0.3 明确不做

以下能力不属于第一版，不得以“顺便实现”为由插入 MVP：

- PDF、Word、PPTX、音视频等教学材料解析；
- Web 搜索、RAG、引用溯源和事实核验；
- interactive HTML、3D、模拟实验和 PBL；
- 多智能体教师、同学圆桌讨论和 LangGraph；
- 白板、聚光、激光笔和复杂动作编辑；
- 图片、视频、音色克隆、云端 TTS/ASR；
- 专业幻灯片编辑器；
- PPTX、HTML、ZIP、MP4 导出；
- 登录、权限、多租户、云同步；
- PostgreSQL、对象存储、任务队列和微服务；
- 同一课程内的动态模型路由、自动择模和并行多模型生成；
- 国际化和移动端/窄屏专项适配；现有小屏样式可以继续保留为 best-effort 行为，但不作为 M7～M10 的实现承诺或验收条件。

这些能力不能反向改变 M1～M6 的完成定义。MVP 验收通过后，只有被新版本明确选中的能力才成为开发承诺。

### 4.3 v0.4/M7～M10 计划范围

v0.4 以“课程质量、PPT 式只读幻灯片与多样化互动能力”为产品主题，拆为 M7～M10 四个独立退出阶段，详细任务和验收见 [09-v0.4-quality-and-interaction-plan.md](09-v0.4-quality-and-interaction-plan.md)。新生成课程只保留这一种 PPT 式 slide 表达，不再建设类 Markdown、纵向讲义或同课双视图。本版本必须交付：

M8～M10 只承诺最新版 Chrome/Edge 下 `1280×720` 及更大桌面视口。移动端、平板和小于 1280px 的窄屏不要求专门布局、截图或 E2E；已有媒体查询和自然缩放无需删除，但只按非阻塞 best-effort 处理。

- 原样保存用户的主题/自然语言课程描述，并将其中明确写出的要求与可选高级设置、服务端默认值归一为 CourseBrief；在 MySQL 持久化受众、学习者水平、学习目标、先修知识、时长、教学风格、互动偏好、附加要求、每字段来源和解析警告；只有主题仍为必填项；
- 升级大纲和场景 Prompt，使目标、场景角色、案例/练习、常见误区和测验之间具有可追踪关系；
- 在 M8 裁剪 OpenMAIC 的 `slide-content Prompt → GeneratedSlideData/PPTElement → normalize → Slide → SlideCanvas` 纵向链：模型直接返回 `text/shape/line/code` 的坐标和样式，服务端只做过滤、默认值、文本净化、id 分配和装配；
- 明确区分可见短内容与 narration，以 OpenMAIC 的画布、对齐、留白、字号和输出前自检规则约束页面，并用 3 个真实主题的 `1280×720` MHTML 人工调整 Prompt；
- 增加 diagram/simulation/game/code 互动场景，按教学意图选择 Prompt；允许 CDN 和网络依赖，在无同源权限的 sandbox iframe 中运行；
- 支持 ready 场景按用户简短意见单独再生成，失败时保留原场景；
- 建立固定质量集、人工量表、成本/延迟记录和 v0.3/v0.4 成对比较。

M7～M10 明确不加入 LangGraph、多智能体、多模态、RAG、媒体生成、3D/procedural-skill widget、服务端任意代码执行。M8 复用 OpenMAIC 的做法让模型直接输出有限 PPTElement 的坐标和样式，但不允许模型控制实体 id、状态、revision、Action、React 或可执行 slide HTML；服务端不再增加通用自动排版和几何评分系统。编辑器仅作为可选 M11，不阻塞 v0.4。编程实验支持浏览器 Worker 中的 Python/JavaScript，支持停止和运行超时，不建设通用代码评测平台。

2026-08-27 冻结的 M7.0 六题输入已经完成 v0.3 生成。2026-08-28 将视觉留档收束为每个已保存场景一份 `1280×720` MHTML；旧双视口截图、DOM 密度观察和空评分表已退出当前方案，但原课程、失败样本、生成元数据和错误记录不变。M8～M10 产品退出只覆盖桌面端，人工量表和既定阈值不得因看到 v0.4 候选结果而临时放宽。

### 4.4 M11/M12 可选扩展边界

M11 是 PPT 式幻灯片编辑器，不是另一种课程展示形态。它必须复用 M8 的只读 SlideCanvas 和 `Slide/PPTElement`，只在其上增加选择、拖拽、缩放、文字编辑、撤销重做和 MySQL revision 保存。M11 不得建立独立的编辑器文档格式，也不得让编辑器状态替代 CourseRepository 中的课程事实。

M12 是简化资源包导出，不进入 v0.4 完成标准。其唯一目标结构为：

```text
课程名称.zip
├─ 课程名称.pptx
└─ interactive/
   ├─ 03_流程互动.html
   └─ 07_知识结构图.html
```

PPT 式 slide 按课程顺序写入 PPTX；interactive 场景按原始 `Scene.order` 命名为自包含 HTML。第一版资源包不额外生成 manifest、README 或 assets 目录，外部资源离线打包在 M12 单独设计，当前保存 HTML 不承诺完全离线。M11 和 M12 都只能在 M10/v0.4 完成后按需启动，均不作为毕业论文延展的前置条件。

## 5. MVP 完成标准

只有同时满足以下条件，才能宣布“可运行基线系统完成”：

| 编号 | 验收条件 | 验证方式 |
|---|---|---|
| AC-01 | 全新环境按 README 可以安装并启动 | 人工按步骤执行 |
| AC-02 | `AI_MODE=mock` 时无需模型网络和 Key 也能在本地 MySQL 上走完整流程 | Playwright |
| AC-03 | 输入合法主题后生成 4～8 个大纲项 | 单元测试 + 人工 |
| AC-04 | 用户确认大纲后能生成 slide 和 quiz，slide 可安全显示静态代码块 | 集成测试 |
| AC-05 | 非法模型 JSON 不会进入持久化层 | Schema 测试 |
| AC-06 | 某场景失败时，成功场景保留且失败项可重试 | 集成测试 |
| AC-07 | 课堂能上一页、下一页、播放、暂停和继续 | Playwright |
| AC-08 | quiz 能提交答案并展示解析 | Playwright |
| AC-09 | 刷新或重启应用后可以从 MySQL 重新打开已生成课程 | Playwright |
| AC-10 | 不启用或无法使用语音时，文本/计时播放仍可完成课程 | 单元测试 + 人工 |
| AC-11 | 模型 Key 和数据库凭据不出现在客户端 bundle、响应或浏览器存储中 | 构建检查 + 人工 |
| AC-12 | lint、test、build 全部通过 | CI 或本地命令 |

仅有页面、仅能调用模型、仅展示一段文本或只在开发机偶然成功，均不算完成。

## 6. v0.4/M7～M10 完成标准

v0.4 的“完成”以 M10 退出为准，同时要求产品链路、画布质量、运行安全和课程质量四类证据，不能只用 iframe 能打开、画布能显示或模型调用成功代替：

| 编号 | 验收条件 | 验证方式 |
|---|---|---|
| AC-Q01 | CourseBrief 按“显式设置 > Prompt > 默认值”解析，字段来源、警告和大纲可从 MySQL 同 revision 恢复 | Schema + API + MySQL 集成 |
| AC-Q02 | v1 课程无需清库即可读取并迁移到 v2 | 迁移 fixture + MySQL 集成 |
| AC-Q03 | outline.v2 在同一次正常调用中解析描述并生成大纲；场景 Prompt 实际使用已保存的受众、目标、时长、风格和课程记忆 | Prompt golden + 调用计数 + 生成测试 |
| AC-Q04 | 新 `content.canvas` 只包含允许的 `text/shape/line/code`，经轻量规范化和 text 净化后可从 MySQL 恢复，并在 `1280×720` 及更大桌面视口由只读 SlideCanvas 渲染；坏元素不会造成白屏 | Schema + normalize + 组件测试 + 3 个真实主题 MHTML + 桌面 E2E |
| AC-Q05 | `interactionMode=required` 按4/5～6/7～8场景分别安排1/1～2/1～3个互动 | Schema + API 集成 |
| AC-Q06 | 互动 HTML 经过大小、自包含、外部依赖和最小协议检查后才能持久化 | validator 测试 |
| AC-Q07 | iframe 无 `allow-same-origin`、无外部网络，并正确处理 ready/reset/completed/error | 安全测试 + Playwright |
| AC-Q08 | 互动生成失败或运行失败不会丢失其他场景，并提供 fallback 与单场重试 | 故障注入 + E2E |
| AC-Q09 | ready 场景再生成成功时原位替换，失败或冲突时保留旧结果 | 应用服务 + MySQL 集成 |
| AC-Q10 | 使用 M7.0 相同六题与固定桌面配对规则，相对 v0.3 达到人工质量阈值，并报告延迟、token 和修复次数 | 桌面成对人工评价报告 |
| AC-Q11 | M6 的 AC-01～AC-12 与 `pnpm verify:full` 继续通过 | 全量回归 |

### 质量阈值冻结规则

M7.0 已用当前 Prompt v1 和固定六题建立历史基线，M10 必须复用相同输入和本文既定的桌面配对维度与阈值，防止根据候选结果修改评分标准。既定质量阈值不因删除移动端交付要求而放宽；该规模只用于 M10 产品质量退出，不直接充当论文实验结论。

## 7. 技术与运行约束

- 采用现有 Next.js App Router 单体工程；
- 浏览器端和服务端统一使用 TypeScript；
- MVP 远端生成只要求 DeepSeek，通过 OpenAI-compatible 接口接入；已有百炼兼容配置不构成交付承诺；
- 模型生成存在延迟和随机性，界面必须显示阶段与错误；
- Next.js 服务端通过 CourseRepository 独占访问 MySQL，浏览器不能直连数据库；
- v0.4 仍是单用户系统，不实现认证；因此只部署在本机或受信任网络；
- Web Speech API 是可选能力，其声音和可用性由操作系统与浏览器决定；
- 项目不训练模型，不包含 GPU 推理服务；
- 开发期间保留 mock 模式，防止 UI、测试和演示完全依赖外部 API。

## 8. 主要风险及控制方式

| 风险 | 影响 | 控制方式 |
|---|---|---|
| 把完整 OpenMAIC 当作交付范围 | 无法按期完成 | 以本文件“不做清单”为变更门禁 |
| 模型输出不稳定 | 页面崩溃或生成中断 | Zod、一次修复、类型化错误、单场景重试 |
| 先接模型再做 UI | 前后端问题耦合 | M1 必须先用 fixture 跑通纵向闭环 |
| API 费用和限流 | 无法连续调试 | mock 模式、场景上限、调用硬上限 |
| 数据库连接或迁移失败 | 课程无法创建或恢复 | 启动健康检查、版本化迁移、事务和备份说明 |
| 浏览器 TTS 差异 | 播放体验不一致 | 文本回退和时间估算，不把 TTS 作为数据正确性条件 |
| 设计文档长期失真 | 实现与论文不一致 | 每个里程碑完成时同步修改文档 |
| 直接复制上游代码 | 学术贡献不清 | 记录来源、保留许可证、区分参考与独立实现 |
| 生成脚本逃逸或访问网络 | 主应用数据和用户环境受影响 | sandbox、CSP、无同源权限、消息来源校验和危险 HTML 测试 |
| 只优化页面外观 | 课程仍然泛化和空洞 | CourseBrief、教学结构 Prompt、质量量表与成对基线同时推进 |
| 互动范围继续膨胀 | 失败类型和测试矩阵失控 | 当前四类型共享同一HTML/iframe链路，不增加3D、服务端执行或通用插件SDK |

## 9. 变更控制

新增功能进入当前版本前必须回答三个问题：

1. 它是否是当前版本验收条件中的必要前置？
2. 不实现它，核心闭环是否仍然可以运行？
3. 它是否会引入新的外部服务、数据类型或长期维护负担？

若第一题为“否”且第二题为“是”，默认放入后续版本。范围变更必须同时更新本文件、需求文档和路线图，不能只在代码中悄悄扩大。

## 10. 与毕业论文的关系

v0.3 是可运行工程基线，v0.4/M7～M10 是课程质量、PPT 式幻灯片和互动能力的产品基线；两者可支撑需求分析、系统设计、实现和测试章节，但都不自动等于研究创新。M10 通过后才进入暂存的 MX 论文选题，并在同一基线上定义：

- 明确的问题与输入输出；
- 可复现的基线方法；
- 可量化指标；
- 对照实验和必要的消融实验；
- 对成本、延迟、稳定性和质量的边界说明。

在 M10 质量数据和运行证据形成前，不提前承诺 LangGraph、多智能体或多模态方向，也不把使用某个框架本身描述为创新。
